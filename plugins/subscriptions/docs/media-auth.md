# Интеграция защищённых видео и архивов камер

Плагин принимает решение о доступе на сервере и выдаёт короткоживущий подписанный токен. Токен привязан к пользователю, типу и идентификатору ресурса, разрешению, временному диапазону и сроку действия. Во время проверки право запрашивается заново, поэтому окончание или отзыв подписки действует сразу.

## Получение токена

Авторизованный клиент делает POST-запрос с обычной CSRF-защитой FIREBALL CMS:

```text
POST /subscription-media/token/camera_archive/{camera_id}
from=2026-08-09T09:00:00Z
to=2026-08-09T09:15:00Z
download=0
```

Для платного видео используется `/subscription-media/token/video/{video_id}`. Ответ содержит `token` и `expires_in`. Разрешение выбирается сервером (`camera_archive.view`, `camera_archive.download` или `videos.view_paid`), а не передаётся клиентом.

Диапазон `from`/`to` обязателен для архива камеры. Принадлежность камеры группе никогда не принимается от клиента. Её должен вернуть доверенный серверный интеграционный hook:

```php
add_filter('subscriptions_camera_groups_for_resource', static function (array $groups, string $cameraId): array {
    return MyCameraRepository::groupIdsForCamera($cameraId);
}, 10);
```

## Серверная проверка

Перед отдачей файла или плейлиста медиасервис вызывает:

```text
GET /subscription-media/validate/camera_archive/{camera_id}?token={token}
```

Успешный ответ имеет HTTP 200 и `{"status":true,"context":{...}}`; любой просроченный, изменённый или отозванный токен получает HTTP 403. Идентификаторы ресурса в URL выпуска и проверки должны совпадать. Медиасервис обязан сравнить запрошенный временной диапазон с подписанными `context.from` и `context.to`.

Рекомендуемый поток:

1. приложение выдаёт токен после проверки подписки и ограничений тарифа;
2. клиент передаёт токен серверу медиа;
3. сервер медиа вызывает endpoint проверки;
4. только после HTTP 200 сервер отдаёт HLS-плейлист, сегмент или файл.

## Требования к веб-серверу

- храните исходные файлы вне публичного document root либо запретите их прямую раздачу;
- используйте `auth_request`, внутренний location, `X-Accel-Redirect`, `X-Sendfile` или эквивалентную серверную схему;
- не полагайтесь на скрытые ссылки, JavaScript или проверку только на странице плеера;
- передавайте реальный `camera_id` и группы камеры; тариф может ограничивать глубину архива, длительность фрагмента и скачивание;
- не кэшируйте положительный ответ проверки дольше срока токена.

Конкретная конфигурация Nginx/Apache зависит от маршрута медиасервера. Главный инвариант: без HTTP 200 от endpoint проверки защищённые байты не должны покидать сервер.
