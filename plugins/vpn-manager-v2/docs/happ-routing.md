# Маршрутизация Happ

Доступна с версии 0.25.0 в разделе **Управление VPN → Настройки → Маршрутизация Happ**.

1. Скопируйте готовую ссылку маршрутизации из 3x-ui или создайте правила в [редакторе Happ](https://routing.happ.su/).
2. Вставьте ссылку `happ://routing/add/…` / `happ://routing/onadd/…` либо JSON-профиль Happ с непустым полем `Name`.
3. Включите «Применять маршрутизацию в Happ» и сохраните настройки.
4. В Happ обновите существующую подписку сайта и переподключите VPN. Менять ссылку подписки не требуется.

После сохранения в настройках и в кабинете владельца активной подписки доступны кнопки «Применить в Happ» и «Скопировать маршрутизацию». Для ручного применения нужен установленный Happ. При отказе браузера в копировании появляется поле для ручного копирования. Кнопка использует сохранённый профиль; сначала сохраните изменения формы.

Правила общие для подписок этого плагина. Профиль с тем же `Name` обновляется в Happ. Ссылки `add` преобразуются в `onadd`, чтобы импорт активировал профиль. Плагин не выбирает страны, домены или исключения самостоятельно: используются правила администратора.

Чтобы отключить ранее переданную маршрутизацию, снимите переключатель, оставьте ссылку в поле и сохраните настройки. После обновления подписки Happ получит команду отключения. Очистка поля полностью прекращает передачу команд маршрутизации; уже импортированные настройки на устройстве она не удаляет.

## Передача и совместимость

- В активных ответах подписки передаются HTTP-заголовки `routing: happ://routing/onadd/{base64}` и `routing-enable: true`. Для отключения настроенного профиля передаются `routing: happ://routing/off` и `routing-enable: 0`.
- Заголовки доступны для обычного и Base64-форматов подписки, включая ответы из кэша и `304`. Список подключений и их количество не меняются.
- При сохранении изменённой ссылки или переключателя обновляются версии конфигураций и сбрасывается кэш через существующий механизм плагина. Истёкшие и недоступные подписки правила не получают.
- По умолчанию профиль пуст и отключён; маршрутизация на устройстве не меняется. Миграция БД не требуется: параметры хранятся в `plugin_settings`.
- Принимаются встроенные профили Happ. HTTP(S)-адреса удалённых JSON-файлов и полные Xray-конфигурации не поддерживаются этим полем. Для импортируемого профиля нужны `Name` и правила в формате Happ.
- Готовая ссылка ограничена 4096 байтами для совместимости с распространёнными ограничениями HTTP-заголовков. Ввод JSON ограничен 65536 байтами. Перед сохранением проверяются JSON, имя, списки правил и флаги `GlobalProxy`/`FakeDNS`; неизвестные поля сохраняются для совместимости с новыми версиями Happ.
- Эффект настроек на устройстве наступает после переподключения. Если Happ загружает GeoIP/GeoSite-файлы, дождитесь завершения загрузки. Для JSON-подписок Happ действуют отдельные ограничения; плагин выдаёт обычную подписку со списком URI.

## Проверки

`php plugins/vpn-manager-v2/tests/happ_routing_unit.php` проверяет импорт, Unicode, отбраковку некорректных ссылок, заголовки, отключение и HTML кнопок без БД.

`php plugins/vpn-manager-v2/tests/stage11_integration.php` проверяет сохранение, реальные ответы подписки, кэш, ETag и данные кабинета на локальной БД CMS. Фикстуры выполняются в транзакции с откатом; удалённые 3x-ui не вызываются.

Протокол сверён с [документацией Happ](https://github.com/HappDev/happ_su/blob/main/dev-docs/routing.md) и [выдачей заголовков 3x-ui](https://github.com/MHSanaei/3x-ui/blob/main/internal/sub/controller.go) 12 сентября 2026 года.
