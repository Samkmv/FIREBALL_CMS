# Smart Connect и резервирование — VPN Manager V2 1.6.0

Дата проверки документации и тестов: 10 октября 2026 года.

В версии 1.6.1 отдельно добавлена [защита просмотра и экспорта в Happ](connection-protection.md). Она работает независимо от Smart Connect; не является отзывом уже скопированного ключа.

## Что делать администратору

1. Обновите VPN Manager V2 штатным обновлением плагинов CMS. Миграция `019_add_server_health.sql` создаёт только таблицы диагностики. На этой локальной установке миграция применена интеграционным тестом; настройки теста откатились. На другом сайте обновление нужно применить отдельно. Не запускайте интеграционные тесты на рабочем сайте.
2. Откройте **Управление VPN → Ещё → Настройки → Smart Connect**. Новый блок находится между настройками подписки и маршрутизацией Happ. Все новые функции по умолчанию выключены.
3. Для Happ включите **Smart Connect**, выберите **Автоматически**, включите **Управлять автоматическим подключением Happ**. Укажите Provider ID, полученный в `happ-proxy.com`. Оставьте проверку при открытии, сортировку и автоподключение включёнными; метод — **Через прокси · GET**.
4. Сохраните настройки. Пользователь обновляет **существующую обычную подписку** в Happ. Новую подписку в CMS, новые UUID или клиентов в панели создавать не нужно. При следующем открытии Happ получит параметры выбора. Реальное применение заголовков проверьте на используемой версии приложения.
5. Если требуется резервирование во время работы, включите **Разрешить отдельную подписку sing-box JSON**, выберите режим **Автоматически с резервированием · sing-box**. Начните с интервала **180 секунд**, порога **100 мс**. Пользователь копирует отдельную ссылку **Профиль sing-box** из своих подключений или карточки подписки администратора и добавляет её как **удалённый профиль** в клиент, принимающий полный sing-box JSON.
6. **Проверьте HWID до выбора клиента.** Для подписок с лимитом устройств загрузчик профиля должен передавать `X-HWID`; CMS сохраняет существующий контроль через панель. Обычный SFA/SFI без этого заголовка получает отказ. Поддержка JSON сама по себе не означает поддержку HWID. Не отключайте действующие ограничения ради экспорта. Для подписок без HWID-ограничения отдельный JSON доступен обычным совместимым клиентам.
7. При желании включите **Фоновый мониторинг** и запустите штатный CLI-планировщик. Это отдельная диагностика; она не нужна клиенту для выбора узла и может работать независимо от общего переключателя Smart Connect.
8. До включения для всех клиентов проведите сценарии проверки ниже на тестовой подписке и физических устройствах.

## Значение настроек

| Настройка | Действие |
| --- | --- |
| Включить Smart Connect | Разрешает новые параметры Happ и дополнительный формат sing-box. Выключено по умолчанию. |
| Ручной | Обычные URI выдаются как раньше; управляющие заголовки Happ не отправляются. В явно разрешённом JSON используется selector с первым узлом по порядку. |
| Автоматически | Happ выбирает при запуске; JSON sing-box использует urltest для последующих соединений без принудительного разрыва уже открытых. |
| Автоматически с резервированием | В JSON sing-box включается прерывание существующих соединений при смене выбранного узла. Happ сохраняет только возможности выбора при запуске. |
| Управление Happ | Отправляет подтверждённые заголовки только при включённом Smart Connect и автоматическом режиме. |
| Provider ID | Идентификатор провайдера Happ. Это публичный параметр подписки, не API-пароль. Без него управление Happ не включается. |
| Проверять при открытии | Happ запускает тест узлов при открытии приложения. Не означает непрерывный контроль. |
| Сортировать по задержке | Happ показывает узлы по результатам проверки. CMS не меняет сохранённую ручную сортировку. |
| Автоподключение | Выбор `lowestdelay` при запуске Happ. Проверка при открытии обязательна, чтобы не опираться только на старый результат. |
| Метод проверки Happ | Только proxy GET или proxy HEAD. TCP и ICMP в Smart Connect не предлагаются: они не доказывают работоспособность VPN-туннеля. |
| HTTPS-адрес проверки | Общий адрес, который клиент запрашивает через VPN-узлы. Короткий ответ 204 предпочтителен. Не указывайте секреты, локальные адреса или пользовательские идентификаторы. |
| JSON sing-box | Отдельная полная конфигурация, **не замена** стандартного списка URI. Требует совместимого загрузчика профиля и движка 1.12+. |
| Интервал sing-box | 30–1800 секунд между проверками активной группы. По умолчанию 180. Частые проверки увеличивают расход батареи и трафика. |
| Порог sing-box | 1–5000 мс; по умолчанию 100. Работающий выбранный узел сохраняется, пока другой не станет быстрее больше этого порога. При отсутствии успешной проверки этот порог не удерживает неисправный узел. |
| Приоритет сервера | 0–1000, меньше — выше. Определяет порядок кандидатов до первых результатов и при первоначальном равенстве. Не перевешивает измеренную задержку. При уже выбранном исправном узле hysteresis сохраняет его. Не меняет порядок обычной подписки и Happ. Внешние узлы без соответствия локальному серверу получают 1000. |
| Фоновый мониторинг | Проверяет инфраструктуру от CMS; хранит состояние и ограниченную историю, ничего не переключает у пользователя. |
| Интервал проверки серверов | Уже существующая настройка ниже блока Smart Connect; используется новым мониторингом. При ошибках пауза растёт до часа либо до исходного интервала, если он больше часа. |

Параметры Happ могут сохраняться в приложении. Отключение функции в CMS прекращает отправку заголовков, но не гарантирует сброс ранее сохранённых настроек самого приложения. Для возврата старого пользовательского поведения отключите автоподключение/сортировку в Happ вручную. Неактивная подписка, пока управление Happ включено, явно отправляет отключение автоподключения и проверки.

## Подтверждённые возможности клиентов

| Клиент/формат | Выбор | Отказ во время работы | Ограничения |
| --- | --- | --- | --- |
| Happ, обычная подписка URI | Proxy-проверка, сортировка, lowestdelay при открытии, с Provider ID | Через используемые заголовки не документирован | Не заявляем live failover; обновить подписку и проверить версию приложения |
| sing-box 1.12+, полный JSON | urltest, результаты на устройстве, интервал и tolerance | Выбор резервного узла средствами движка; в режиме failover `interrupt_exist_connections=true` | Смена не переносит открытый TCP-сеанс; приложения должны повторить запрос/соединение. HWID-загрузчик обязателен при соответствующем лимите |
| SFA/SFI, удалённый полный профиль | Возможности встроенного совместимого sing-box | Те же механизмы urltest | Формат, сборка с транспортами, право TUN, версия ОС и HTTP-заголовки профиля требуют проверки на устройстве |
| Другие приложения, принимающие только VLESS/VMess/Trojan URI | Сохраняется их обычное поведение | Ничего нового не обещается | Не добавлять JSON-ссылку в несовместимый импортёр |

`subscription-autoconnect` в Happ относится к открытию приложения. Его нельзя считать мониторингом активного VPN. `fallback-url` в документации Happ относится к загрузке подписки, а не переключению VPN-узлов; в эту реализацию он не добавлен.

Xray имеет Observatory/Burst Observatory и балансировщики, но обычный URI не переносит полную конфигурацию балансировщика. Эта версия не подменяет подписки Xray JSON и не вмешивается в действующие правила Happ.

### Заголовки Happ

| Заголовок | Отправляемые значения |
| --- | --- |
| `providerid` | Проверенный по безопасному синтаксису введённый ID; без CR/LF |
| `subscription-ping-onopen-enabled` | `1` / `0` |
| `subscription-autoconnect` | `1` / `0` |
| `subscription-autoconnect-type` | `lowestdelay`, только при включённом автоподключении активной подписки |
| `subscriptions-sort-type` | `ping` / `without` |
| `ping-type` | `proxy` / `proxy-head`, только активная подписка |
| `check-url-via-proxy` | Проверенный HTTPS URL, только активная подписка |

Happ также документирует `lastused`, `random`, `alphabet`, `tcp`, `icmp`; они не используются для этого алгоритма оптимального выбора. Из наличия механизма в документации не следует, что конкретная версия iOS/Android применит его без обновления подписки или разрешений пользователя.

Получение Provider ID и его работа описаны Happ: приложение выполняет ежедневный запрос к сервису Happ с идентификатором провайдера, хешем домена подписки, HWID, названием и версией ОС. CMS показывает это администратору до включения функции и сама не отправляет такой запрос. Идентификатор виден получателю подписки; не используйте вместо него секрет API. Новые журналы не содержат Provider ID, VPN-ключей, токенов подписок или пользовательских сетевых данных.

## Архитектура

```text
SettingsRepository → SettingsValidator / SmartConnectValidator → VpnSettingsData
                                  ↓
SubscriptionEndpoint → срок/статус/зависимости → существующий HWID gateway
                                  ↓
       Metadata + HappSmartConnect → ETag / Last-Modified / 304
                                  ↓
       VpnSubscriptionBuilder → локальные узлы + зависимые + внешние snapshots
                  ├─ base64/plain (тот же URI-список)
                  └─ format=singbox → SingBoxSubscriptionBuilder → полный JSON

CLI/Jobs → ServerHealthMonitorService → ServerHealthRepository
          отдельная диагностика; не влияет на состав подписок
```

Settings сохраняются в штатной `plugin_settings`, отдельная система подписок не создаётся. Изменения управляющих параметров включены в существующий механизм ревизий и инвалидации. Токены, пароли и UUID не меняются. Форматы base64/plain/singbox имеют отдельные ключи кэша и ETag; очистка ревизии удаляет все три. Ответ 304 содержит актуальные метаданные Happ. Доступ и HWID проверяются раньше кэша/304.

`VpnSubscriptionBuilder` продолжает применять текущие проверки, last-known-good данные, порядок, зависимости и приоритет собственных конфигураций при устранении дублей. Внешние данные берутся из существующих зашифрованных снимков; endpoint не скачивает внешние подписки и не выполняет новый мониторинг.

Ссылка для JSON: существующий `/vpn-v2/subscription/<token>?format=singbox`. Default URL, QR и URI-форматы сохраняются. Формат определяется только явным параметром, никогда по User-Agent. При выключенном экспорте JSON возвращается 404.

### Профиль sing-box

Экспортируется полный профиль: TUN, IPv4/IPv6-адреса, auto-route, strict-route, DNS через выбранную группу и локальный bootstrap resolver для доменов VPN-узлов, urltest/selector и прокси-выходы. Direct-резерв для пользовательского трафика не добавляется. Bootstrap DNS разрешает адреса узлов через системный DNS вне туннеля; это необходимый этап запуска, он не является прокси-проверкой. DNS приложений идёт через выбранную группу и DNS hijack; DoH `1.1.1.1` с SNI `cloudflare-dns.com` используется в этом первом профиле.

Поддерживаются VLESS, VMess, Trojan; TCP/raw без HTTP-маскировки, WS, обычный gRPC и HTTPUpgrade; TLS, uTLS, Reality/Vision в пределах поддерживаемых полей. Для внешних источников также поддержан SIP002 Shadowsocks с AES-128-GCM, AES-256-GCM и chacha20-ietf-poly1305 без plugins. Сохраняются реальные учётные данные, адреса, порты, SNI, ALPN, Host/path и соответствующие параметры.

Экспорт строго отказывает при XHTTP/SplitHTTP, HTTP-маскировке TCP, неподдерживаемых расширениях (например, PQV), gRPC authority/multiMode, Shadowsocks plugins и неизвестных существенных параметрах. Нельзя молча удалить узел или расширение и выдать обещание рабочего Failover. Экспорт такой подписки возвращает 422 с безопасным сообщением; стандартные URI сохраняются. Reality `spx` является Xray spider path и не имеет аналога в экспортируемом sing-box TLS; он не превращается в ложный параметр движка.

При истечении, приостановке, удалении, будущем начале или превышении лимитов JSON обновляется в профиль с пустыми прокси и безусловным `reject`, минуя кэш и 304. Ранее скачанные файлы/клиенты, не обновившие подписку, всё равно требуют штатного ограничения на удалённой панели — это не новый механизм отзыва доступа.

## Восстановление и устойчивость

Проверки urltest происходят через каждый прокси на устройстве пользователя. После запуска и затем по интервалу движок обновляет историю успешных задержек, убирает результат неудачной проверки и выбирает доступный выход. Ошибки подключения также сбрасывают соответствующую историю. Следующие проверки снова позволяют выбрать восстановившийся узел. Пока текущий узел доступен, tolerance защищает от смены из-за небольших колебаний задержки. Режим failover разрешает движку закрыть существующие входящие соединения при смене выбора. Длительные сеансы, звонки и скачивания могут прерваться; непрерывность отдельного TCP-сеанса не гарантируется.

В изученном urltest нет отдельных настроек «несколько ошибок подряд», blacklist cooldown или экспоненциального backoff клиента. Их не имитируем в CMS и не показываем неработающие переключатели. Интервал ограничивает частоту проверок, tolerance обеспечивает hysteresis по задержке. Это не универсальная защита от всех чередующихся сбоев: для строгого временного cooldown потребуется другой документированный клиентский механизм.

У движка есть idle timeout 30 минут. Когда группа долго не используется, проверки могут приостановиться и возобновиться при обращении. Возобновление после смены сети зависит от клиентского frontend/ОС; мгновенная перепроверка при Wi-Fi/LTE через CMS не гарантируется. Если все узлы недоступны, запросы завершаются ошибкой; прямой обход VPN не включается.

CMS никогда не выбирает узел на основании того, как этот узел доступен с хостинга CMS. Поэтому блокировка адреса конкретным оператором не отключает его для остальных клиентов.

## Мониторинг инфраструктуры

Миграция 019 добавляет `vpn_v2_server_health` и `vpn_v2_server_health_checks`; до 50 последних проверок на сервер. Включённое задание обрабатывает один просроченный сервер за запуск, пропускает выключенные/обслуживаемые серверы и сериализует работников advisory lock без ожидания.

Проверка панели использует существующий `ThreeXuiClient::serverStatus()` с таймаутами connect 2 s / read 4 s и штатным ограниченным процессом авторизации. Метрики нормализует `ServerMetricsService`. Состояние Xray — running/stopped/error/unknown. Проверяются до восьми включённых локальных inbounds; TCP connect — максимум 1 s на порт, адрес проходит существующую защиту от частных сетей и фиксируется для сокета. DNS использует системные ограничения резолвера. Для доверенной частной сети действует уже существующая административная настройка сервера.

TCP-проверка не выполняет WS/gRPC/Reality/TLS-рукопожатие и не доказывает работоспособность транспорта; каждый порт хранит `tunnel=unverified`. UDP/KCP не объявляются успешными через TCP. CPU/память/load/network, время последней проверки/успеха и последовательные ошибки сохраняются отдельно от подписок.

Состояния карточки: «Инфраструктура доступна» — панель отвечает, Xray running и проверенные TCP-порты открыты; «Требует проверки» — часть данных неизвестна или проверка порта/движка не прошла; «Панель недоступна» — запрос статуса не прошёл, в том числе из-за авторизации. Ни один статус не означает доступность для всех операторов.

После неудачи первая пауза равна настроенному интервалу, затем удваивается до часа/исходного большего интервала; успех сбрасывает счётчик. История сохраняется, last_success не стирается. Snapshot содержит фиксированные коды ошибок вместо исключений с секретами. Мониторинг не обращается к операциям add/update/delete клиента, не изменяет состав подписки, ревизию, UUID или enabled сервера. Открытие настроек читает только сохранённые результаты.

Задание опубликовано через существующие фильтры планировщика как `vpn_v2_server_health`. Если общего worker нет, запускайте CLI:

```sh
php plugins/vpn-manager-v2/cron.php --health-only
```

Например, в cron каждую минуту, с реальным PHP и абсолютным путём к вашему CMS:

```cron
* * * * * cd /path/to/FIREBALL_CMS && /path/to/php plugins/vpn-manager-v2/cron.php --health-only
```

Обычный запуск `cron.php` также включает мониторинг, если он разрешён. Это не заменяет фоновые задания трафика и полной синхронизации. Не запускайте cron через публичный HTTP: entrypoint принимает только CLI.

## Диагностика

| Симптом | Проверка |
| --- | --- |
| Happ не выбирает автоматически | Provider ID, общий переключатель, режим, управление Happ, обновление подписки, параметры приложения. Сравнить активный ответ 200/304 с таблицей заголовков. |
| Happ не переключился при активном сбое | Эти заголовки не предоставляют подтверждённый live failover. Проверить вручную или использовать совместимый JSON-клиент. |
| JSON 404 | Выключен export, неправильная ссылка либо HWID не поддержан. При HWID ответы содержат штатные `X-Hwid-*`/`X-Fireball-HWID-Gate`. |
| JSON 503 | Недоступна обязательная проверка HWID панели. Лимит остаётся защищённым; это не обходится сменой формата. |
| JSON 422 / `X-Fireball-VPN-Config: unsupported` | Неподдерживаемый транспорт/параметры. Обычная подписка работает; проверить inbounds и внешние источники. Не удалять пользователей ради экспорта. |
| Все узлы «недоступны» только в клиенте | Проверить тестовый HTTPS-сайт, DNS, часы/TLS, сеть и блокировки. Общий недоступный тестовый сайт может испортить результаты всех узлов. |
| CMS зелёная, на LTE VPN не работает | Нормально для операторской блокировки: инфраструктурная проверка не заменяет проверку через прокси с устройства. |
| Мониторинг без результатов | Переключатель, миграция 019, CLI-worker, доступ к БД, enabled/maintenance серверов, права сетевых запросов хостинга. |
| Постоянные переключения sing-box | Увеличить tolerance, использовать разумный интервал, проверить нестабильный канал. Отдельного временного cooldown в urltest нет. |
| Подписка истекла, старый файл ещё работает | Обновить профиль, проверить удалённые expiry/disable и штатные jobs. Уже сохранённые ключи не отзываются одним изменением подписки. |

Не публикуйте полный URL подписки, URI, HWID и ключи в тикетах или логах. Для поддержки достаточно статуса HTTP, фиксированного кода, времени, версии клиента и описания воспроизводимого сценария без идентификаторов.

## Что проверять на телефонах

Happ iOS/Android, SFA Android и SFI Apple **не проверены на физических устройствах**. Нельзя переносить результат локального CLI на них как гарантию. Запишите версию приложения/движка и результаты отдельно.

| Сценарий | Happ | sing-box-профиль |
| --- | --- | --- |
| Wi-Fi, все узлы доступны | Обновить подписку, закрыть/открыть, убедиться в proxy-проверке и lowestdelay | Проверить импорт, TUN, DNS, urltest и проходящий трафик |
| LTE, один IP недоступен | Повторить открытие/проверку; должен выбираться доступный по возможностям Happ | Дождаться проверки, подтвердить резервный узел с устройства |
| Блокировка порта/транспорта | Проверка через прокси должна выявлять отказ, TCP/ICMP недостаточно | Подтвердить отказ нужного транспорта и выбор резервного |
| Сбой активного сервера | Не ожидать документированного переключения через эти headers | Проверить смену узла, повтор запросов приложения и допустимое прерывание TCP/звонка |
| Возвращение узла | Новая проверка при открытии | Следующий urltest; не переключаться обратно из-за небольшой разницы задержки |
| Wi-Fi → LTE → Wi-Fi | Проверить поведение каждой версии/ОС, при необходимости открыть приложение заново | Проверить реакцию frontend/ОС, TUN/DNS, переоценку после смены сети |
| Все узлы недоступны | Показать отказ, не обещать подключение | Отказ соединений; убедиться, что пользовательский трафик не ушёл напрямую |
| Истечение/приостановка | Обновить обычную подписку, проверить отключение autoconnect | Обновить JSON, проверить reject; проверить удалённые сроки/disable |
| Лимит устройств/HWID | Проверить штатную регистрацию и отказ лишнему устройству | Сначала проверить, отправляет ли загрузчик X-HWID; без него доступ не предоставляется |

Для тестирования блокировок используйте тестовый сервер/сетевое правило на стенде; не меняйте пользователей или ключи рабочих подписок. Наблюдайте одновременно клиентскую проверку и обычные реальные запросы через VPN, а не только API панели.

## Расширение

Можно добавить отдельный экспорт Xray Observatory/Balancer для клиента с подтверждённой поддержкой полного JSON; предварительно решить совместимость с маршрутизацией Happ. Другие возможности: профильные DNS-настройки sing-box, новые безопасные преобразователи транспортов после официальной поддержки, ограниченные транспортные проверки инфраструктуры без сохранения пользовательских секретов, клиент с документированными cooldown/failure threshold. Эти функции сейчас не представлены как реализованные.
