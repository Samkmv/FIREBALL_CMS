# Защита от передачи подключений — VPN Manager V2 1.6.1

Проверено по официальной документации 10 октября 2026 года.

## Что происходит при копировании

**Копирование уже полученного VLESS/VMess/Trojan-ключа само по себе не отключает его.** Импортированный ключ обращается прямо к VPN-серверу и может работать без повторной загрузки подписки. В текущей интеграции HWID ограничивает получение подписки, а не каждый сеанс Xray. Xray аутентифицирует клиента по UUID/паролю, а не доказывает, что это прежнее физическое устройство.

Скопированный ключ использует того же удалённого клиента: общий трафик, срок и серверное состояние доступа. После подтверждённого отключения/удаления этого клиента либо применения срока и лимитов в панели доступ ограничивается для оригинала и копии. Момент прекращения уже открытого соединения зависит от движка и фоновой обработки панели; отдельной гарантии мгновенного разрыва нет.

Удаление HWID из списка устройств не является отзывом уже выданного UUID. Не путайте ограничение загрузки подписки с серверной привязкой каждого VPN-сеанса.

## Как запретить обычное копирование в Happ

1. Откройте **Управление VPN → Ещё → Настройки → Безопасность**.
2. В карточке **Защита подключений в Happ** выберите **Запретить просмотр и экспорт**.
3. Сохраните настройки.
4. Пользователь обновляет существующую обычную подписку в Happ. Ссылка и ключи остаются прежними.
5. На физическом устройстве проверьте, что отдельное подключение нельзя просмотреть, редактировать или передать через копирование, QR либо JSON.

CMS отправляет документированный стандартный заголовок `hide-settings: 1`. Настройка не зависит от Smart Connect, автоматического выбора или маршрутизации и не требует Provider ID. Заголовок передаётся как в 200, так и в 304, а также для неактивного URI-профиля. HWID-проверка для активной подписки остаётся раньше ответа и кэша.

Три режима:

| Режим | Что отправляет CMS |
| --- | --- |
| Не менять настройки приложения | Заголовок отсутствует. Это режим по умолчанию для прежних установок. Он не обещает сброс сохранённого параметра Happ. |
| Запретить просмотр и экспорт | `hide-settings: 1`. Happ скрывает конфигурации подписки и их обычный экспорт. |
| Разрешить просмотр и экспорт | `hide-settings: 0`. Явное отключение этой политики для обычной подписки. Дополнительные ограничения зашифрованной подписки Happ могут сохраняться. |

Для возврата из ранее применённого запрета выберите **Разрешить просмотр и экспорт**, сохраните и обновите подписку в Happ. Простого прекращения передачи заголовка может быть недостаточно для сброса настроек приложения.

## Границы защиты

`hide-settings` ограничивает **интерфейс совместимого Happ**. Эта настройка не делает ключ технически непереносимым: владелец обычного URL подписки получает данные через HTTP, другие приложения могут игнорировать заголовок, а ранее извлечённые ключи продолжают использовать общую серверную учётную запись. Не вводятся фильтры User-Agent как ложная защита: их можно подделать.

Отдельный полный JSON sing-box также содержит рабочие ключи. В таком ответе `hide-settings` намеренно отсутствует; нельзя заявлять запрет экспорта для стороннего клиента. Администратор, которому нужна защита интерфейса именно Happ, должен учитывать, что разрешённый экспорт JSON предоставляет другой способ получения конфигурации.

В интерфейсе настройки показаны эти ограничения. CMS не меняет UUID/пароли, не удаляет устройства или клиентов, не закрывает действующий VPN и не собирает новые данные о пользователе ради скрытия меню.

Для более сильной защиты интерфейса Happ официально предусмотрены `happ://crypt5/`-ссылки, которые также скрывают адрес подписки. Генерация нового формата использует внешний API Happ. В этом изменении такая интеграция **не включена**: секретные ссылки подписок не передаются внешнему сервису. Старое локальное RSA-шифрование `crypt4` помечено Happ как устаревшее и не добавляется в качестве новой функции. Даже шифрование ссылки не превращает уже извлечённый UUID в аппаратно привязанный ключ.

Жёсткая защита каждого сеанса требует поддерживаемого сервером и приложением способа привязки/аттестации устройства. Он отсутствует в применяемых обычных протоколах и текущем HWID gateway. Периодическая замена всех UUID ради борьбы с копиями не реализуется: это затронет действующие подключения, особенно устройства, которые не обновили подписку.

## Проверки

- `happ_protection_unit.php`: 25 сценариев — defaults без изменений, строгая валидация, хранение/DTO, оба значения заголовка, независимость от Provider ID/Smart Connect, маршрутизация, четыре языка.
- `smart_connect_integration.php`: расширен до 39 сценариев — реальное сохранение трёх политик, неизменный URI-payload, обновлённая ревизия и заголовки 200/304, неактивные подписки, HWID перед кэшем, отсутствие ложной защиты в JSON и стабильные UUID/токены/порядок. Тестовые записи и настройки откатываются.
- `smart_connect_browser.cjs`: форма защиты включена в проверку RU/EN/DE/ZH на 320/390/768/1440 px.

Автоматические тесты проверяют CMS. Они **не подтверждают поведение установленного Happ**. На iOS и Android отдельно проверить: обновление старой подписки; отсутствие копирования/QR/JSON у скрытого узла; обычное VPN-подключение; явное снятие запрета; блокировку лишнего устройства при загрузке; прекращение доступа оригинала и копии после серверного отключения на тестовом клиенте.

## Изменённые файлы

По отношению к завершённому Smart Connect изменены:

- `src/DTO/VpnSettingsData.php`, `src/Validators/SettingsValidator.php`, `src/Services/SettingsService.php` — типизированная политика, сохранение и ревизии.
- `src/Services/VpnSubscriptionMetadataService.php`, `src/Services/VpnSubscriptionEndpointService.php` — `hide-settings`, cache/304/неактивный профиль и исключение JSON.
- `views/admin/settings.php`, `lang/ru.php`, `lang/en.php`, `lang/de.php`, `lang/zh-cn.php` — карточка, переводы и честное описание ограничений.
- `tests/happ_protection_unit.php`, `tests/smart_connect_integration.php`, `tests/smart_connect_browser.cjs` — проверки.
- `plugin.json`, `docs/smart-connect.md`, `docs/connection-protection.md` — выпуск и инструкции.

Отдельная миграция не требуется: политика хранится в существующих настройках плагина. Новые сетевые вызовы не добавлены.
