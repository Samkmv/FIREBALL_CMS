# Синхронизация воспроизведения — Tape Room 1.7.7

Для вошедшего пользователя сервер сохраняет песню, позицию в секундах, очередь
с порядком, режимы повтора и перемешивания. При открытии другого устройства
серверная запись имеет приоритет над старой записью браузера. Автоматического
запуска звука нет: Play продолжает прослушивание на выбранном устройстве.
Предыдущий работающий плеер получает новое состояние и ставится на паузу.

Синхронизация выполняется примерно раз в пять секунд, при управлении плеером
и возвращении на страницу. На принимающем устройстве время отображается
между запросами без запуска аудио и без постоянной перемотки загружаемого файла.
При недоступности сети локальное воспроизведение продолжается. Браузер может
задерживать запросы в фоне или при блокировке телефона; переключение не является
мгновенной командой через постоянное соединение.

Тема, громкость, вид плеера и открытый раздел остаются настройками устройства.
Браузерные torrent-песни не загружаются на сервер и не становятся переносимой
записью воспроизведения. Загруженные в CMS и доступные через Google Drive песни
используют обычные серверные ссылки и синхронизируются.

## Хранение и защита

Миграция `012_playback_sync.sql` добавляет таблицу `reel_playback_state` с одной
строкой на аккаунт и внешним ключом на пользователя. Аудиофайлы не копируются.
Сохраняются только разрешённые поля; нет произвольных URL, путей, токенов,
громкости или данных другого аккаунта.

`GET /tape-room/api/playback` читает состояние вошедшего пользователя.
`POST` принимает JSON с `device`, `seenDevice`, `revision`, `claim`, `playing`
и `state`. Оба маршрута требуют авторизации, запись требует CSRF; ответы имеют
`Cache-Control: private, no-store`. Пользователь определяется сессией.
Текущая песня и очередь проверяются по владению и одобренной публикации.

Запись блокируется транзакцией по пользователю. Фоновое обновление принимается
только от текущего устройства с актуальной ревизией. Явное продолжение может
сменить устройство, если прежний владелец совпадает с известным отправителю.
Свежий клик один раз повторяет запрос после уточнения владельца; старый запрос,
отложенный из-за потери связи, не перехватывает более позднее воспроизведение.
Задержавшиеся ответы чтения не отменяют новое действие пользователя.

## Проверка

`tests/tape_room_sync.cjs` проверяет порядок запросов, запоздавшие ответы,
конфликты, передачу управления, ограниченную оценку позиции и потерю сети.

`tests/tape_room_sync_check.py` работает с отдельным сервером
`tests/tape_room_fixture.php`. Подготовьте уникальный каталог внутри
`tests/.tmp/` через `tests/tape_room_fixture_setup.py`. Для аватара сервер
запускается с `TAPE_ROOM_TEST_PUBLIC=1`, чтобы реальные методы загрузки CMS
писали файлы исключительно в тестовый каталог. Тесту передаётся тот же
`TAPE_ROOM_TEST_ROOT`; нужны подготовленные `avatar.png` и `bad-avatar.svg`.
Сценарий проверяет две независимые сессии аккаунта, чужие аккаунты, CSRF,
доступ к песням, ревизии, старый запрос перехвата и штатную загрузку аватара.

В браузере дополнительно проверены независимые ключи локального хранилища,
восстановление песни без автозапуска, продолжение с другого устройства,
порядок плейлиста, обе темы аккаунта и мобильные размеры 320/390 пикселей.
