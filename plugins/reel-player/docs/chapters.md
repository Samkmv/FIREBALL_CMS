# Главы и CUE в Tape Room 1.3.0

Главы размечают композиции внутри одной длинной записи: название, необязательный исполнитель и время начала. Выбор главы перематывает существующий HTML Audio к таймкоду. Исходный файл остаётся целым; разметка работает с локальными записями и Google Drive независимо от доступности автопоиска.

## Редактор и воспроизведение

В редакторе песни **О композиции** доступны **Добавить таймкод** и **CUE и автопоиск**. Начало вводится как `ММ:СС` или `ЧЧ:ММ:СС`, при необходимости с дробной частью до шести знаков: `01:23.493333`. Кнопка **Использовать текущее время** берёт позицию выбранной записи. Для сохранения обязательно название; исполнитель необязателен. Глава редактируется и удаляется отдельно от аудиофайла.

При выборе размеченной записи появляется список глав с поиском по названию и исполнителю. Текущая глава подсвечивается и подписывается над управлением. На шкале времени отображаются маркеры после получения длительности; на узком экране при нажатии выбирается ближайший таймкод. Доступны подписи и управление с клавиатуры.

Кнопки предыдущей и следующей композиции, включая команды Media Session, сначала переключают главы текущей записи. Следующая переходит к ближайшей следующей главе; после последней применяется обычная очередь файлов. Предыдущая возвращает к началу текущей главы, если прошло больше трёх секунд, иначе — к предыдущей; на первой главе возвращает к её началу. Если позиция находится до первой главы, предыдущая возвращает к нулю. Переключение главы не перезагружает источник и не сбрасывает очередь Shuffle.

Естественный конец файла использует обычные настройки очереди и повтора. Repeat одной песни повторяет всю запись, Shuffle перемешивает файлы. Для файлов без глав поведение очереди сохраняется. При запросе перемотки до загрузки метаданных позиция ожидает готовности того же источника; восстановление после ошибки сохраняет выбранный таймкод.

## Хранение и границы

Миграция [`004_chapters.sql`](../migrations/004_chapters.sql) добавляет таблицу `reel_chapters`:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `BIGINT UNSIGNED` | Идентификатор главы |
| `track_id` | `BIGINT UNSIGNED` | Запись из `reel_tracks` |
| `title` | `VARCHAR(240)` | Обязательное название |
| `artist` | `VARCHAR(240)` | Необязательный исполнитель, по умолчанию пустой |
| `start_time` | `DECIMAL(12,6)` | Начало в секундах |

Внешний ключ удаляет главы при удалении записи (`ON DELETE CASCADE`). Уникальный индекс `(track_id, start_time)` исключает повтор одного таймкода. На одну запись разрешено до 1000 глав. Начало должно быть конечным числом от 0 до 604800 секунд; при известной длительности — строго меньше её. Значения нормализуются до шести знаков, проверяются на дубли и сортируются по времени. Название и исполнитель проверяются как UTF-8, до 240 символов.

[`Repositories/Chapters.php`](../src/Repositories/Chapters.php) проверяет владельца записи для чтения и каждой операции. CRUD и импорт выполняются в транзакции с блокировкой строки записи `FOR UPDATE`. Замена проверяет полный список до удаления; ошибка вставки откатывает всю операцию. Добавление сохраняет существующие главы и их идентификаторы. Изменение длительности использует ту же блокировку и отклоняет значение, которое оставляет главы за концом записи.

[`Repositories/Library.php`](../src/Repositories/Library.php) добавляет массив `chapters` каждому треку в состоянии библиотеки. Все главы владельца выбираются одним запросом с соединением `reel_tracks`, без отдельного запроса на каждую песню. Публичная запись имеет вид:

```json
{"id":17,"track_id":4,"title":"Первая композиция","artist":"Исполнитель","start":83.493333}
```

## API

Все маршруты требуют авторизованного создателя или администратора CMS. POST-запросы проходят обычную проверку CSRF; интерфейс передаёт `needCSRFToken` и `X-CSRF-Token`. Запросы относятся только к собственной библиотеке пользователя. Ответы JSON содержат `status`; ошибки данных возвращают HTTP 422 и `message`.

| Маршрут / действие | Данные | Результат |
| --- | --- | --- |
| `GET /admin/reel-player/api/state` | — | Библиотека; у каждого трека `chapters: []` или отсортированный массив |
| `POST /admin/reel-player/api/action`, `chapter.create` | `track_id`, `title`, `artist`, `start` в секундах | `id` новой главы и обновлённая библиотека |
| Тот же маршрут, `chapter.update` | `track_id`, `id`, изменяемые `title`, `artist`, `start` | Обновлённая библиотека |
| Тот же маршрут, `chapter.delete` | `track_id`, `id` | Обновлённая библиотека |
| Тот же маршрут, `chapter.import` | `track_id`, `chapters` как JSON-строка массива, `mode`, `revision`; для замены `confirmed=1` | Атомарный импорт и обновлённая библиотека |
| `POST /admin/reel-player/api/chapters/cue` | multipart: `track_id`, файл `cue` | Предпросмотр `entries`, `warnings`, `encoding`, `file`, `existing`, `total`, `mode`, `revision` |
| `POST /admin/reel-player/api/chapters/analyze` | `track_id` | Предложения `entries` / `chapters`, `warnings`, `method`, `duration`, `partial`, `recognitionAvailable`, `revision` |

Действия передаются полем `action`; остальные поля — обычной формой. `mode=merge` добавляет главы, `mode=replace` заменяет всю разметку одной записи. Предпросмотр ничего не сохраняет. Пользователь выбирает строки, исправляет время и текст, выбирает режим и нажимает **Сохранить таймкоды**. При наличии глав интерфейс по умолчанию предлагает добавление.

Предпросмотр возвращает SHA-256 ревизию существующей разметки. Интерфейс передаёт её при импорте; сервер проверяет её под блокировкой. Если другая вкладка изменила главы после предпросмотра, импорт отклоняется и требуется новая проверка. Репозиторий также допускает прямой вызов импорта без ревизии; защита от устаревшего предпросмотра требует её передачи.

## Импорт CUE

[`Services/CueParser.php`](../src/Services/CueParser.php) принимает настоящий загруженный `.cue` размером до 1 MiB. Поддерживаются UTF-8 с BOM или без него и UTF-16 LE/BE с BOM. Если текст не является UTF-8, применяется Windows-1251 с предупреждением проверить текст: эта кодировка предполагается, а не определяется достоверно.

В CUE обязателен ровно один `FILE`, соответствующий выбранной записи. Сравнивается имя файла без каталогов и без учёта регистра, включая пути с Windows-разделителями. Пути из CUE не открываются и не загружаются. Разметка другого файла, нескольких файлов или дорожек не типа `AUDIO` отклоняется.

Каждая дорожка должна содержать один `INDEX 01 MM:SS:FF`; кадры `FF` находятся в пределах 0–74 и переводятся в секунды как `FF / 75`. `INDEX 00` и другие индексы пропускаются с предупреждением. `TITLE` задаёт название главы, `PERFORMER` дорожки — исполнителя; общий `PERFORMER` используется как запасное значение. Если `TITLE` отсутствует, показывается редактируемое имя **Глава XX** с предупреждением; это не распознавание названия.

Повторные начала, некорректные кадры, превышение лимита и конфликт с известной длительностью отклоняются до сохранения. При неизвестной длительности предпросмотр предупреждает проверить границы после начала воспроизведения. Дробные секунды сохраняются в редакторе, включая таймкоды CUE.

## Автопоиск и его ограничения

[`Services/ChapterAnalysis.php`](../src/Services/ChapterAnalysis.php) ищет реальные паузы ниже −38 dBFS длительностью от 0,8 секунды. Начало следующего слышимого участка предлагается как переход; близкие границы (менее 15 секунд), начальная и конечная тишина исключаются. Максимум — 500 предложений. Названия и исполнители оставляются пустыми: перед сохранением пользователь заполняет названия выбранных строк. Непрерывный микс может не дать результатов, а тихая часть песни — дать ложную границу.

| Источник | Реализованный анализ | Ограничения |
| --- | --- | --- |
| Локальный PCM / float WAV | Чтение сигнала средствами PHP | PCM 8/16/24/32 бит, float 32/64 бит, до 8 каналов; ограниченные окна в памяти |
| Локальный сжатый файл | `silencedetect` установленного FFmpeg | Требуются доступный FFmpeg и `proc_open`; автоматически ничего не устанавливается; по умолчанию до 45 секунд, один поток и 1 MiB диагностического вывода |
| Google Drive PCM / float WAV до 127 MiB | Чтение диапазонов через всю запись | Файл привязан к `headRevisionId`; до 128 запросов, 128 MiB данных, один диапазон до 2 MiB, бюджет анализа 55 секунд |
| Более крупный Google Drive PCM / float WAV | До 120 коротких окон по 2 секунды | `partial=true`, `method=wav-sampled-silence`; покрытие неполное, границы приблизительны и могут быть пропущены |
| Сжатый Google Drive файл | Автопоиск недоступен | Используйте CUE или ручные таймкоды; воспроизведение и главы доступны |

Диапазоны Drive проверяются на точный размер и `Content-Range`, относятся к одной ревизии и читаются через серверную авторизацию; токены не передаются в браузер или FFmpeg. Анализ не скачивает целую облачную запись для декодирования. Браузер ограничивает ожидание ответа 90 секундами; закрытие окна отменяет его запрос. Сохранённые главы от отмены не меняются, серверная работа завершается в пределах собственных лимитов.

[`Services/ChapterRecognitionProvider.php`](../src/Services/ChapterRecognitionProvider.php) содержит только интерфейс адаптера `identify(authorizedLocalPath, start, sampleSeconds)`. Провайдер распознавания не подключён, аудио никуда для распознавания не отправляется, `recognitionAvailable=false`. Подробности сигнала, диапазонов и будущего адаптера описаны в [документации автопоиска](chapter-analysis.md).

## Проверки

Команды из корня репозитория:

```sh
php tests/tape-room-chapters.php --parser-only
php -d pdo_mysql.default_socket=/Applications/MAMP/tmp/mysql/mysql.sock tests/tape-room-chapters.php
php tests/tape-room-analysis.php
node tests/tape-room-chapters.js
node tests/tape-room-chapter-races.js
node tests/tape-room-ui.js
```

Серверный сценарий проверяет кодировки и кадры CUE, соответствие имени, границы, CRUD, разделение владельцев, merge/replace, конфликт ревизий, настоящий откат MySQL после ошибки вставки, каскадное удаление, один запрос агрегации и гонку изменения длительности. Он создаёт отдельную временную базу и удаляет её после проверки; установленная библиотека не изменяется. Для полного сценария требуется доступ к локальному MySQL с правом создать и удалить тестовую базу. `--parser-only` не требует MySQL.

Анализ проверяется на синтетических WAV с реальным сигналом, длительных виртуальных диапазонах, ограничениях запросов и повреждённых данных. Работа внешнего процесса проверяется тестовой программой с выводом FFmpeg; это не проверка установленного FFmpeg. JS-сценарии покрывают дробные таймкоды, двухчасовую запись с 30 главами, сохранение источника и очереди, переходы до загрузки метаданных и поздние ответы закрытых форм. Браузерный стенд использует отдельные данные; временные файлы находятся в `tests/.tmp/`.

Эти проверки не подтверждают живой вход в Google OAuth и воспроизведение реального Drive-файла, а также ограничения Safari, установленной PWA и фонового режима на физическом iPhone. Их нужно проверять отдельно на подключённом аккаунте и самом устройстве.
