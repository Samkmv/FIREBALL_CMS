# Camera Manager

Плагин автоматизирует схему проекта MAXIPAPA:

`камера → регистратор → WireGuard → RTSP → streams.pl/FFmpeg → HLS → сайт`.

Он хранит объекты, регистраторы и каналы в базе FIREBALL CMS, шифрует RTSP-пароли и публикует отдельный управляемый блок `%cam` в существующий `/var/www/html/rtsp/streams.pl`.

## Рекомендуемое подключение для SprintHost

Для виртуального хостинга используется исходящая синхронизация: RTSP-сервер раз в минуту обращается к FIREBALL CMS по HTTPS и забирает новую ревизию. На SprintHost не требуются SSH, `exec`, `proc_open` или доступ к системным каталогам — достаточно загрузить плагин по FTP и активировать его в CMS.

Запросы подписываются случайным 256-битным токеном. В CMS хранится только SHA-256 хеш токена, а его исходное значение находится в root-only конфигурации RTSP-сервера. RTSP URL передаются только в HTTPS-ответе с `Cache-Control: no-store`.

Полная установка: [`server/README.md`](server/README.md).

## Защита существующих камер

Перед каждым применением RTSP-агент:

1. блокирует параллельную публикацию;
2. формирует временный файл в каталоге `streams.pl`;
3. доказывает побайтовую неизменность всего файла за пределами маркеров `FIREBALL CAMERA MANAGER: BEGIN/END`;
4. отклоняет совпадение ключа новой камеры с ручной или старой записью;
5. разрешает внутри блока только RTSP-элементы строгого формата;
6. выполняет `perl -c`;
7. создаёт резервную копию;
8. атомарно заменяет файл и перезапускает `rtsp-streams.service`;
9. автоматически возвращает исходный файл, если служба не запустилась.

Таким образом, первая публикация добавляет новый блок рядом с существующими камерами, а дальнейшие публикации меняют только этот блок.

## Режимы

- `HTTPS pull` — рекомендуется для SprintHost и другого виртуального хостинга.
- `SSH` — альтернативный push-режим с отдельным Ed25519-ключом и forced-command агентом.
- `Локальный файл` — если CMS и RTSP находятся на одном сервере.

## Установка плагина

1. Загрузите каталог `camera-manager` по FTP в каталог `plugins` FIREBALL CMS.
2. В панели FIREBALL CMS откройте «Плагины», установите и активируйте Camera Manager.
3. Откройте «Камеры → Настройки», выберите `HTTPS: RTSP-сервер забирает настройки` и настройте общий токен по инструкции сервера.
4. Сначала запустите агент без камер и убедитесь, что CMS видит его обращение.
5. Создайте объект и камеры, проверьте «Конфигурацию» и нажмите «Опубликовать».

Приватные ключи WireGuard в плагин не вводятся. Изменение `wg0.conf` намеренно не автоматизировано: ошибка в нём может отключить все действующие объекты. Мастер отдельно показывает параметры Keenetic/Netcraze для рабочей `/24` сети, серверный `[Peer]` и безопасную последовательность ручных команд: резервная копия `wg0.conf`, `wg set`, затем `wg syncconf` после ручного добавления peer-блока. PHP-код эти команды не запускает.

## Подключение нового объекта

После сохранения объекта откройте «Объекты → Подключение». Мастер не выполняет root-команды, а формирует безопасные инструкции и ставит ограниченные проверки в очередь HTTPS pull-агента.

Пример без реальных credentials:

```text
Объект:       34
Router:       192.168.34.1
VPN:          10.10.0.34
LAN:          192.168.34.0/24
Recorder:     192.168.34.100
RTSP:         554
External RTSP: 55434
```

Полный lifecycle:

1. заполнить LAN, router/VPN IP, recorder и только WireGuard `PublicKey`;
2. скопировать параметры peer в Keenetic/Netcraze и блок `[Peer]` для сервера;
3. вручную настроить firewall роутера для WireGuard → LAN;
4. вручную применить маршрут `ip route replace 192.168.34.0/24 dev wg0`;
5. скачать и проверить `ipt.tun.034.up.sh`/`ipt.tun.034.down.sh`;
6. нажать «Проверить подключение» — агент последовательно проверит peer, route, ICMP, TCP и RTSP;
7. подтвердить найденный RTSP profile и добавить канал;
8. проверить masked preview и опубликовать существующим HTTPS pull;
9. открыть HLS: `{hls_base}/stream-34-01/index.m3u8`;
10. проверить poster: `{hls_base}/tn-34-01.jpg`.

Первый запрос HLS будит FFmpeg. Поэтому первоначальный HTTP 404 отображается как `HLS pending`; при отсутствии запросов поток может заснуть примерно через 120 секунд.

## RTSP profiles

- Dahua: `/cam/realmonitor?channel={channel}&subtype={subtype}`;
- Dahua legacy: `/cam/realmonitor?channel={channel}_subtype={subtype}`;
- Hikvision / HiWatch ISAPI: `/ISAPI/Streaming/Channels/101`, `102`, `201`, `202`;
- Hikvision Streaming: `/Streaming/Channels/101` и далее;
- Generic channel/stream: `/?channel={channel}_stream={stream}`;
- Custom: прежний `rtsp_path_template` без изменения существующих объектов.

## Безопасная диагностика

CMS не обращается к `192.168.x.x`. Она хранит задание фиксированного типа, а обновлённый pull-agent выполняет только:

```text
wg_peer
route_check
ping_check
tcp_check
port_discovery
rtsp_probe
hls_check
```

Текст shell-команды из CMS не принимается. Все IP, порты, интерфейсы, PublicKey и RTSP paths валидируются повторно на сервере. RTSP-пароль передаётся помощнику через stdin, не записывается в очередь/результат и не выводится в журнал.
