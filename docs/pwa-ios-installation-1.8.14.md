# FIREBALL CMS 1.8.14 — иконка в окне установки iPhone

На присланном снимке iPhone показывает букву T уже в окне «На экран Домой». Проверка tape-room.ru обнаружила доступные PNG по ссылкам HTML/манифеста, но стандартный `/apple-touch-icon.png` отвечал 404. Это недостаток резервного обнаружения иконки, а не доказательство единственной причины сбоя конкретного iPhone.

Apple описывает корневой PNG и явный `apple-touch-icon` в [Safari Web Content Guide](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariWebContent/ConfiguringWebApplications/ConfiguringWebApplications.html). В 1.8.14 добавлена совместимая выдача этого изображения:

- `/apple-touch-icon.png` и `/apple-touch-icon-precomposed.png` доступны без входа по GET и HEAD и возвращают непосредственно PNG 180×180.
- HTML ссылается на корневой адрес без query-параметров и предварительно загружает ту же картинку.
- Ответ имеет ETag по фактическим байтам и `Cache-Control: public, max-age=0, must-revalidate`. Смена картинки в админке меняет ETag; прежний валидатор больше не получает 304.
- Используется выбранный ранее растровый набор, включая старые плоские наборы в uploads и перенесённые legacy-наборы. При стандартной картинке учитывается `images/apple-touch-icon.png` активной темы. SVG/favicon остаётся отдельным ресурсом, для установки выдаётся реальный PNG.
- Запрос изображения не генерирует файлы и не создаёт изменяемый PNG в корне public. Системные иконки остаются нетронутыми; новые маршруты не возвращают произвольные пути из query-параметров.
- При отсутствии корректного изображения возвращается пустой 404, а не HTML с успешным статусом. Корневой адрес не попадает под статический кэш service worker.

В образец `docs/deployment/nginx.conf` добавлены точные location для обоих адресов: это нужно для конфигураций, в которых общая обработка PNG иначе возвращает файловый 404 до маршрутизации CMS. Если существующий сервер уже передаёт отсутствующие файлы в index.php, изменения его конфигурации не требуются.

## Проверка после обновления сервера

1. Установить полную версию CMS 1.8.14. Если старый обновлятор заблокирован, сначала выполнить порядок из `updater-1.8.13-migration.md`.
2. Открыть `https://ваш-сайт/apple-touch-icon.png`: должна отображаться выбранная картинка, ответ — 200 image/png без перенаправления на вход.
3. Закрыть открытое окно добавления на iPhone, обновить страницу сайта в Safari и заново открыть «На экран Домой».

Серверные HTTP-проверки не подтверждают исправление системного окна конкретного iPhone. Если буква остаётся после выкладки, нужна проверка на этом устройстве; версия iOS и браузер помогут отличить проблему загрузки от системного кэша. Очистка локальной музыкальной библиотеки для этой проверки не требуется.

## Проверки реализации

`python3 tests/pwa_installation_check.py` запускает настоящий роутер CMS, контроллер, helpers и генерацию в изолированной установке с SQLite. 21 проверка охватывает GET/HEAD, тему и загруженную картинку, HTML/preload, смену ETag, 304, старый precomposed-адрес, SVG, PNG манифеста Android, неизменность системных иконок и отсутствие HTML вместо изображения. Временные данные и процесс сервера удаляются по завершении.

Для другой среды путь к PHP задаётся через `FBL_TEST_PHP`; необходимы PHP 8.2+, GD и PDO SQLite. Отчёты находятся в `tests/artifacts/pwa-installation/`. Дополнительно прошли 50 проверок PWA/миграции из `tests/update_center_runtime.php` и проверка реального localhost:8888.
