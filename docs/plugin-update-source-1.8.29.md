# Доступ к источникам обновлений плагинов — CMS 1.8.29

## Что воспроизведено

На скриншоте Maxipapa все шесть плагинов показывают «Источник обновления плагина недоступен». Это ошибка проверки источника, до скачивания и проверки исходного пакета.

В прежнем коде одна проверка шести плагинов требовала 12 REST-запросов GitHub: шесть одинаковых запросов состояния ветки и шесть манифестов. Ошибки HTTP 401, 403, 404, 429 и 500 скрывались за одним текстом, а неудачный результат автоматически перепроверялся только через шесть часов. Эти дефекты воспроизведены изолированными тестами.

GitHub связывает неавторизованную REST-квоту с исходящим IP сервера, а не доменом: [официальная документация](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api). Поэтому сайты на разных серверах или с разными токенами могут вести себя по-разному. Неверный токен тоже мог блокировать доступ даже к публичному репозиторию.

**Какой именно ответ получил сервер Maxipapa, по старому сообщению определить невозможно.** Доступа к его закрытой диагностике при разработке не было. Ошибка сайта не объявляется доказанным ограничением квоты: для её точного подтверждения нужен ответ его сервера после выкладки или соответствующий журнал.

## Изменения

- Публичная ветка определяется через HTTPS Git `info/refs` один раз на пакетную проверку; манифесты читаются через `raw.githubusercontent.com` по одному неизменяемому SHA коммита. Необязательный токен туда не отправляется.
- Новый пакет и исходный пакет для проверки скачиваются через `codeload.github.com/…/zip/{SHA}`. Адрес не содержит `refs/heads/`, и смена ветки между проверкой и скачиванием не меняет выбранный пакет.
- Для приватных репозиториев и недоступных публичных узлов сохранён API-вариант. Все прежние ограничения HTTPS, адресов, перенаправлений, размеров, ZIP, совместимости, резервирования и атомарной замены продолжают действовать.
- HTTP 401, запрет доступа, отсутствие файла, ограничение запросов, ошибка сервера и ошибка соединения теперь различаются. Произвольное тело ответа, токены и внутренние сетевые подробности в сообщение не копируются. Переводы есть на четырёх языках.
- Успешный результат хранится шесть часов, ошибка проверки — пять минут. Если GitHub сообщил `Retry-After` или срок восстановления квоты, автопроверка ждёт этого срока, с защитным пределом 24 часа. Заголовки промежуточного ответа не переносятся в окончательный.
- Поиск неизвестного исходного пакета по истории и подтверждение дополнительных Git-файлов всё ещё могут требовать REST API. При его отказе проверка останавливается с конкретной причиной: обхода защиты локальных файлов и принудительного обновления нет.

Всего **230 проверок**. Дополнительно выполнена разовая проверка реального источника: манифесты всех шести плагинов прочитаны за семь HTTPS-запросов, без токена и REST API. Отработанный сетевой пробник и его временный отчёт удалены после проверки; постоянные автономные регрессии сохранены.

Боевые файлы и база Maxipapa не изменялись. После публикации изменений владельцем нужно обновить ядро до 1.8.29 и повторить «Проверить все плагины». Новая конкретная ошибка, если она останется, позволит отличить ограничение сети самого хостинга от проблемы источника.
