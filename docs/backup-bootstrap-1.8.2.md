# Как разблокировать обновление CMS 1.8.2

4 октября 2026 года. Архив: `dist/fireball-backup-bootstrap-1.8.2-2026-10-04.zip`.

## Подтверждённая причина

В журнале сервера за 13:08:31 и 13:08:43 резервное копирование остановлено старой службой: `Automatic recovery does not support views, triggers, routines or events; update aborted.` Это проверка из релиза 1.8.2. В VPN установлены штатные триггеры проверки элементов подписки.

Обновление отменяется до замены файлов. Поэтому исправление, уже включённое в релиз 1.8.4, не может установиться через кнопку «Обновить»: сначала нужно один раз заменить службу копирования вручную.

## Что входит в исправление

Архив содержит две службы, инструкцию и контрольные суммы:

- `app/Services/Maintenance/DatabaseBackupService.php` — копирование данных вместе с триггерами; проверка полной видимости объектов понимает также перечисленные права MySQL 8.
- `app/Services/UpdateRecoveryService.php` — восстановление сохранённых триггеров после загрузки данных, с исходными DEFINER, SQL_MODE, кодировкой и составными SQL-телами.

Оба файла совпадают с файлами опубликованного в локальном Git тега `1.8.4`. Они совместимы с остальным кодом 1.8.2; зависимости и версия CMS этим архивом не заменяются. Здесь нет базы, паролей, конфигурации, загрузок и файлов плагинов.

Службы нужно переносить вместе: новый формат копии с триггерами требует соответствующего восстановления. Триггеры VPN не удаляются. При неподтверждённых правах, MyISAM, views, routines или events обновление по-прежнему останавливается; это исправление не разрешает обновление без полной копии.

## Как применить

1. Сделайте резервную копию файлов и БД через панель хостинга. Сохраните исходные версии двух заменяемых PHP-файлов вне публичной папки сайта. На время переноса остановите обновления и фоновые задачи, включите обслуживание на уровне хостинга.
2. Распакуйте архив во временную папку. Перенесите только два PHP-файла из `app`, сохраняя пути, в корень установленной CMS: `/home/maxipapa/domains/maxipapa.ru/public_html`. Если у этих служб есть собственные изменения, сначала сравните их с исправлением.
3. Перезапустите PHP/PHP-FPM в панели хостинга, чтобы очистить OPcache и загрузить новый код. Пересборка CSS и миграции для этих двух файлов не нужны.
4. Верните доступ к сайту и фоновые задачи. В центре обновлений повторите проверку и установку 1.8.4.

После переноса номер установленной CMS останется 1.8.2 до завершения обычного обновления. Если копирование снова остановится, откройте новую запись `Database backup failed` в `tmp/error.log`: теперь нужно проверить её актуальную причину. Не отключайте резервное копирование ради продолжения установки.

## Проверка совместимости

- На текущих службах: 35 проверок установки, отказа обновления, восстановления и конкурирующих операций в отдельной временной MySQL-БД.
- На исходниках тега 1.8.2 с заменой только двух PHP-файлов: те же 35 проверок успешно пройдены. Восстановлены оба штатных триггера VPN и составной триггер; проверены определения, режим SQL, кодировка и точность восстановленных данных.
- Общие проверки политики копирования: 19; проверки безопасности релиза: 62.

Рабочая локальная БД и серверные файлы сайта во время проверок не изменялись.
