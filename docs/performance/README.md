# Оптимизация FIREBALL CMS — итоговый отчёт

Проверка завершена 13 сентября 2026 года. Отчёт охватывает ранее внесённую оптимизацию ядра и заключительный проход по поиску, плагинам, резервному шаблону и фоновым запросам. Рабочие URL, обязательный PluginInterface и Theme API сохранены. Рабочая БД не переустанавливалась; поисковый индекс обновлён явной командой обслуживания.

## 1. Найденные проблемы

В первоначальном коде обычный запрос мог повторно подключаться к MySQL, проверять установку через information_schema, проверять/менять схему, сканировать плагины и загружать весь набор frontend-библиотек. После первых исправлений при заключительной проверке обнаружились дополнительные проблемы:

- VPN Manager V2 вызывал собственный upgrade service из `boot()`: `SHOW TABLES`, чтение журнала миграций, сканирование SQL-файлов и синхронизация версии на каждом запросе.
- Поиск каждые пять минут пересоздавал индекс прямо в GET. На текущих 36 страницах и одной записи этот сценарий дал **2634 SQL-запроса**.
- Фоновое видео главной автоматически включало FirePlayer/Plyr, хотя использовало самостоятельную HLS-инициализацию.
- Резервный шаблон подключал все библиотеки и повторял `filemtime`; его уведомления опрашивались каждые восемь секунд.
- Медленные запросы чата могли перекрываться; ошибки не снижали частоту опроса.
- Ошибка Cache Storage могла потерять успешно загруженный сетевой ответ Service Worker.

## 2. Изменённые компоненты

Предыдущие этапы: `core/Application.php`, `core/Session.php`, `core/Database.php`, `core/PerformanceProfiler.php`, `core/Cache.php`, `core/Router.php`, `core/AssetManifest.php`, `core/ThemeManager.php`, `core/Plugins/PluginManager.php`, `core/Localization.php`; schema-методы моделей и сервисов; `MigrationRunner`, `SchemaMigration`, `SchemaManifest`, `PublicLayoutContext`, `FrontendAssets`, `LanguagePackService`, `ThemeAssets`; активный публичный layout, JS, `.htaccess` и PWA.

Заключительный проход:

- `app/Search/SearchEngine.php`, `SearchIndexer.php`, `app/Services/SearchMaintenance.php`.
- `app/Models/Admin.php`, `app/Services/InstallService.php`, `UpdateCenter.php`, `bin/cms.php`.
- `core/Plugins/PluginMigrationInterface.php`, `PluginManager.php`, `plugins/vpn-manager-v2/Plugin.php`.
- `app/Services/FrontendAssets.php`, `app/Views/layouts/default.php`, `themes/default/templates/home.php`.
- Обе версии `assets/js/main.js` и `assets/js/chat.js`; `app/Controllers/ChatController.php`.
- `app/Services/PwaService.php`.
- `bin/profile-request.php`, тесты и этот отчёт.

Изменения версии CMS в `config/version.php` и `update.json`, появившиеся параллельно, не выполнялись в рамках этой оптимизации. Ранее сделанные правки поиска и оформления сохранены.

## 3. Application bootstrap и instrumentation

Обычная проверка установки использует lock-файл и конфигурацию. Глубокая проверка вынесена в `inspectInstallation(true)` и CLI `diagnose`. SQL-время, количество запросов, PDO-подключений, DDL/schema-запросов, bootstrap, плагины, router, render, cache и peak memory собираются только при DEBUG/performance debug. Диагностика не содержит текстов SQL и параметров. `Server-Timing` выключен при обычной production-конфигурации.

Для воспроизводимых агрегированных замеров добавлен CLI-only `bin/profile-request.php`; он не создаёт публичный диагностический endpoint.

## 4. Session

Session bootstrap больше не открывает собственный PDO. Политика времени жизни берётся из локальной конфигурации/кеша и уточняется после загрузки общих настроек через основной Database service. Sliding cookie, HttpOnly, Secure, SameSite и strict mode сохранены.

Сессия закрывается после необходимых записей в analytics, unread-count и теперь перед сборкой ответа диалога и потоковой выдачей защищённого вложения. Закрытие не применяется глобально: уведомления допускают сторонние hooks, которые могут работать с сессией.

## 5. Миграции и существующие установки

`MigrationRunner` обрабатывает `config/migrations` и `database/migrations` с общим журналом; одноимённый файл из `database/migrations` имеет приоритет. Используются блокировки и журналирование только успешно завершённых миграций. Совместимость старых schema-методов сохраняет миграция `20260601_legacy_runtime_schema.php`; в обычных запросах эти методы не выполняют DDL.

`SchemaManifest` строится при обслуживании. Отсутствие манифеста не означает отсутствие данных: для проверки существования таблицы разрешён ограниченный `SELECT 1 ... LIMIT 0` с запоминанием результата в запросе, без information_schema.

Для нестандартных миграций добавлен **необязательный** `PluginMigrationInterface::migrateSchema()`. Исходный PluginInterface не изменён. Обычные плагины продолжают использовать SQL-migrations. VPN использует свой upgrade service при install/activate/update/CLI maintenance, сохраняя порядок, журнал, восстановление таблиц и обработку старых credentials; из `boot()` upgrade удалён.

## 6. SiteSetting

Создание таблицы и INSERT IGNORE defaults выполняются в миграции. Чтение использует request-local кеш плюс общий Cache. `setMany()` выполняет пакетный upsert и явную инвалидизацию настроек, публичного контекста и состояния темы. ThemeManager не создаёт таблицу при выборе темы.

## 7. PluginManager

Production boot читает кеш runtime descriptors вместо полного discovery и сканирования миграций. Экземпляр плагина создаётся заново, язык, hooks и маршруты регистрируются в каждом запросе. Проверки исполняемых путей и symlink не удалены. Install/update/activate/deactivate/uninstall инвалидируют runtime manifest.

Заключительный замер подтвердил отсутствие скрытой schema-проверки VPN на главной. Не выполнялись удалённые операции VPN и не изменялись реальные подписки.

## 8. Cache

Используются L1 памяти запроса, необязательный APCu и атомарный файловый кеш. Сохраняются типы значений, включая false/null/0, и TTL. Remove/clear инвалидируют слои; generation-файл связывает инвалидизацию между CLI и web-SAPI. Ошибка записи необязательного кеша не должна превращать публичную страницу в 500. Redis и persistent PDO не требуются.

## 9. Analytics

Создание analytics schema вынесено в миграции. После сохранения landing attribution освобождается блокировка сессии перед GeoIP. Сохраняются UTM, referer, browser/OS/device и география. Внешняя очередь не добавлялась; GeoIP остаётся в существующем сервисе. Localhost исключается из аналитики по существующему правилу private IP.

## 10. Уведомления и чат

Обе версии main.js используют 45-секундный fallback, паузу в скрытой вкладке, обновление при возвращении, backoff до пяти минут, остановку после 401/403 и координацию BroadcastChannel + Web Locks. При недоступности этих API работает обычный опрос. Скоординированные вкладки получают один ответ; явное открытие/обновление может инициировать дополнительный запрос.

Изменение прочитанности инвалидирует находящиеся в полёте ответы, включая другие вкладки. Запоздавший ответ не возвращает старые badges. Сохранены retry, обновление по push-событию, восстановление после BFCache и существующая отрисовка.

Чат сохраняет четырёхсекундный интервал успешного активного диалога, но не запускает параллельные фоновые fetch, имеет 15-секундный timeout и увеличивает интервал ошибок до минуты. Смена контакта отменяет устаревший fetch. Координация разных чат-диалогов между вкладками намеренно не вводилась: их ответы и эффект прочтения различаются.

## 11. Frontend assets

Choices, Simplebar, Swiper, Highlight и player включаются по требованиям шаблона и маркерам HTML. Существующие `styles`, `header_scripts`, `footer_scripts` работают. Резервный публичный layout теперь использует ту же систему и PublicLayoutContext. Для legacy admin-layout сохранён полный набор необязательных vendor-библиотек: динамические формы сторонних плагинов могут создавать элементы после загрузки страницы.

Версии файлов берутся из AssetManifest. Убраны повторные `filemtime` из резервного layout и HLS URL главной. Безопасная проверка ThemeAssets мемоизируется в пределах запроса. Изображения ниже первого экрана используют lazy/async без изменения обработки при GET.

## 12. FirePlayer и HLS

Текстовые страницы не подключают player-библиотеки. Для собственного фонового видео главной добавлен `data-player-native`: оно не требует FirePlayer/Plyr, но остальные video/audio и явный `assets => ['player']` сохраняют прежнее поведение. Главная продолжает загружать HLS только своим существующим механизмом.

В браузере подтверждено: `readyState=4`, `paused=false`, время воспроизведения увеличивается, ошибок video нет, FirePlayer/Plyr scripts отсутствуют. Внутреннее поведение полноценных плееров и fallback native Safari/HLS.js не переписывалось. Отложенная загрузка всего player-набора до IntersectionObserver на страницах с полноценным плеером не вводилась из-за зависимых inline/plugin scripts; безопасное сокращение достигнуто условным подключением.

## 13. Service Worker

Fingerprint static assets — Cache First; изображения — обновление в фоне; navigation — сеть с отдельной offline-страницей. Персонализированный HTML не сохраняется. Исключены admin/api/auth/profile/chat/notifications/search-suggest, изменяющие запросы, Range и медиа/HLS-сегменты. Учитывается подпапка установки и префиксы языков. Размер кеша ограничен, старые версии удаляются при активации.

Дополнительно обработаны quota/denied storage: успешный сетевой ответ возвращается даже при невозможности сохранить его. Push, badge, manifest и install flow сохранены.

## 14. Apache

Cache/compression directives обёрнуты в IfModule. Fingerprinted assets получают `public, max-age=31536000, immutable`; остальные — консервативный expiry. Динамические ответы сохраняют собственную политику. HLS manifests — no-store. Проверен реальный ответ Apache: HTTP 200, immutable Cache-Control, Vary: Accept-Encoding. Compression работает с необязательным Brotli либо gzip.

## 15. Поиск и инвалидизация

SearchEngine больше не вызывает периодическую переиндексацию. Полное начальное заполнение выполняется после установки, обновления CMS и CLI maintenance. Посты/страницы синхронизируют индекс при создании, редактировании, смене публикации и удалении; переименование категории синхронизирует связанные записи. Токены записываются пакетами до 250 вместо отдельного INSERT на каждый токен.

Публичные меню инвалидируются при изменении страниц/постов/категорий/настроек во всех локалях; личные данные, CSRF, flash и пользовательский URL в общий кеш не помещаются. Theme editor и обновления инвалидируют asset versions. Language pack discovery кешируется, обновление CMS/очистка кеша обновляет его.

Плагины, которые изменяют документы вне CMS, должны вызывать существующие `search_sync_entity`/`search_remove_entity` либо явную команду `search:reindex`. `ensureProvidersIndexed()` сохранён как явный maintenance API, но поиск его не вызывает.

Рабочие пользователи и контент при этом не меняются.

Проверены 22 GET-маршрута: главная, архив, категория, запись, контакты, поддержка, поиск/подсказки, en/de/zh-cn, 404, login/register/reset-password, защита profile/admin/notifications/chat, manifest, sw.js и offline. На всех одно PDO-подключение, ноль DDL и schema-запросов, нет 500. Неавторизованные закрытые маршруты корректно возвращают 302. GET `/forgot-password` не является маршрутом приложения: форма использует POST, а reset-token обрабатывает `/reset-password`.

В браузере проверены найденная запись, главная и фоновое видео, ошибок JavaScript не обнаружено. Авторизованные пользовательские сценарии 2FA, отправка push на реальное устройство и Safari воспроизведение не объявляются пройденными end-to-end: для них не использовались реальные credentials/устройства. Совместимость соответствующих механизмов сохранена на уровне кода и границ изменений.

Прогретая главная: медиана семи запусков **66,71 мс**, SQL count во всех семи — 12. Это время CLI PHP с локальным MAMP MySQL, не пользовательский TTFB Apache и не замер production-нагрузки. ## 18. Эксплуатация и намеренно сохранённые ограничения

```sh
php bin/cms.php diagnose
php bin/cms.php migrate
php bin/cms.php search:reindex
php bin/cms.php cache:clear
php bin/profile-request.php '/'
php bin/profile-request.php '/search?q=Техническая'
```

`migrate` предназначен для обновления, не для каждого HTTP-запроса; включает обновление установленных плагинов и поискового индекса. После ручного изменения темы/plugin assets следует очищать кеш. Для providers без событий записи можно запускать `search:reindex` внешним существующим планировщиком по требованиям проекта; новый обязательный сервис не вводился.

Для MAMP CLI в текущем окружении понадобилось `-d pdo_mysql.default_socket=/Applications/MAMP/tmp/mysql/mysql.sock`. Профилировщик принимает `FIREBALL_PROFILE_HOST` для локального host. `FIREBALL_PERFORMANCE_DEBUG=1` следует включать только в контролируемом диагностическом окружении.

Рекомендуется включённый OPcache и разумный memory budget. `opcache.validate_timestamps=0` допустим только при гарантированном сбросе OPcache на каждом deploy; без такого процесса оставьте проверку timestamps. CMS не меняет php.ini.

Намеренно не добавлены: обязательные Redis/CDN, глобальный full-page cache, новая очередь GeoIP, автоматические миграции при GET, удалённые операции VPN, переписывание плееров и обязательная новая инфраструктура. Дальнейшее сокращение legacy admin vendor payload требует отдельной проверки динамических интерфейсов каждого стороннего плагина.
