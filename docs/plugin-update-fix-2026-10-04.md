# Исправление обновлений плагинов, карточек VPN и выбора канала CMS

4 октября 2026 года. Исправление для CMS 1.8.2; оформление VPN — для плагина 1.5.3 с переходом на 1.5.4. Полный релизный ZIP 1.8.2 этим исправлением не заменяется.

## Причина отказа

В присланном журнале обновление subscriptions остановилось до замены файлов: `Automatic recovery does not support views, triggers, routines or events; update aborted.` В VPN есть два штатных триггера из миграции `011_enforce_subscription_item_targets.sql`. Они проверяют допустимые цели элементов подписки; удалять их ради обновления нельзя.

Резервная копия теперь сохраняет триггеры с исходными DEFINER, SQL_MODE, кодировкой и порядком. Восстановление сначала загружает строки, затем создаёт триггеры, включая составные тела с внутренними точками с запятой. Поэтому действия триггеров не меняют восстанавливаемые данные.

Проверка прав также понимает перечисленные глобальные права MySQL 8, а не только `ALL PRIVILEGES`: такой формат предусмотрен [документацией MySQL](https://dev.mysql.com/doc/refman/8.0/en/show-grants.html). Неподтверждённая видимость объектов, MyISAM, views, routines и events по-прежнему останавливают автоматическое обновление. Обновление без полной копии не разрешено.

## Интерфейс

- Карточка плагина отличает ошибку установки от ошибки проверки и показывает безопасное объяснение причины на четырёх языках.
- После ошибки установки проверенная новая версия остаётся доступной для повторного запуска. Ошибка проверки не разрешает установку неподтверждённого пакета.
- Карточки показателей VPN используют цвета админки: серверы — синий, подписки — фиолетовый, подключения — зелёный, тарифы — оранжевый. Реальные ошибки выделяются предупреждением. Поддерживаются светлая и тёмная темы.
- Название, показатели и ошибки расположены отдельными строками. Вертикальная раскладка закреплена в шаблоне и сохраняется даже со старым кэшированным CSS; подписи переносятся, а иконки не сжимаются.
- В центре обновлений создатель выбирает «Релизы и бета-версии» либо «Для разработчиков — main». Выбор сохраняется и применяется к проверке и установке. Администратор всегда получает только стабильные релизы.
- Канал разработчиков проверяет коммиты main и его собственное описание версии. Новые изменения доступны без повышения номера версии и без публикации GitHub Release. Первый переход ZIP-установки без сохранённого коммита на main также доступен; после установки сравниваются коммиты. Проверенные результаты каждого канала хранятся отдельно.
- Кнопка «Обновить» больше не повторяет запрос списка релизов, если успешная проверка этого канала, репозитория и установленной версии моложе шести часов. Установка использует уже показанный опубликованный релиз; проверки пакета и резервное копирование сохраняются. Ошибочные и просроченные результаты, черновики и беты в канале администратора исключены. При исчерпании GitHub API появляется подсказка сохранить токен или повторить проверку позже.

## Как применить на сайте

Архив `dist/fireball-plugin-update-fix-2026-10-04.zip` содержит только изменённые файлы и эту инструкцию. В нём нет конфигурации сайта, базы, загрузок и секретов.

1. Сделайте отдельную резервную копию файлов и БД через панель хостинга. Остановите публичный трафик и фоновые процессы на уровне сервера.
2. Распакуйте исправление во временную папку вне document root. Сравните файлы с установкой и перенесите их, сохраняя структуру каталогов. Если VPN уже новее 1.5.3 либо содержит собственные изменения, перенесите правки отдельно и не понижайте версию.
3. Из корня установки, от владельца файлов веб-приложения, выполните:

   ```sh
   php bin/cms.php cache:clear
   php bin/cms.php assets:rebuild
   ```

   Очистка кэша обновит сохранённые пути плагинов; пересборка ресурсов обновит адреса CSS в браузере. Обе команды требуют отсутствия незавершённого update maintenance. Если обслуживание осталось после другой неудачной миграции, сначала выполните предусмотренное восстановление, а не удаляйте маркер вручную.
4. Перезапустите PHP/PHP-FPM для очистки OPcache. Проверьте вход, плагины и VPN до возврата публичного трафика.
5. В разделе плагинов нажмите «Проверить обновление», затем повторите обновление подписок. Проверьте результат и новые резервные копии.
6. Для получения изменений из main войдите как создатель, откройте «Центр обновлений → Настройки источника», выберите «Для разработчиков — main», сохраните и нажмите «Проверить обновления». Канал «Релизы и бета-версии» использует только опубликованные GitHub Releases.

Исправление меняет общие службы CMS, поэтому его первый перенос выполняется вручную. После применения штатные обновления плагинов с VPN-триггерами снова могут создавать полную резервную копию.

## Проверки

- PHP 8.2: 68/68 наборов; JavaScript: 13/13; синтаксис: 987 файлов.
- Изолированная MySQL: 35 проверок установки, сбоя обновления, восстановления и конкурентных операций. Восстановлены два настоящих VPN-триггера и составной триггер с NO_BACKSLASH_ESCAPES; проверены определения, DEFINER, SQL_MODE и кодировка. Рабочая БД не изменялась.
- Политика резервирования и отображение причины: 19 проверок, также проходят на PHP 8.4.
- Обновления плагинов: 45 проверок, включая возможность повторить установку после отказа копии.
- Каналы CMS: 131 проверка сохранения выбора, доступа, отдельных кэшей, переключения со стабильной версии на main, Git/ZIP, запросов с токеном, исчерпания API, установки проверенного релиза без повторного запроса и четырёх локалей. Настоящий путь ZIP-установки проверен до границы скачивания без изменений рабочей базы и файлов CMS. Браузер: оба канала создателя и стабильный канал администратора на 1440/390, отправка выбора и отсутствие переполнения.
- Браузерные проверки настоящих шаблонов: VPN в обеих темах на 1440/1200/992/390/320, отсутствие переполнения, четыре цвета, предупреждения и раздельные строки, в том числе со старым CSS; плагины — четыре локали и desktop/mobile, плюс шесть сценариев очереди.

Проверки выполнялись локально. Файлы на maxipapa.ru из этого чата не изменялись.
