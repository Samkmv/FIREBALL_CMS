# Widget API FIREBALL CMS

## Подключение и совместимость

Раздел управления: **Внешний вид → Виджеты**, `/admin/widgets`. Маршруты
используют штатные middleware `auth`/`admin`, локализацию, CSRF и AJAX-ответы CMS.
Доступ имеют роли `admin` и `creator`.

Примените миграции штатным способом: `php bin/cms.php migrate`. Миграция
`database/migrations/20261011_create_widgets.sql` создаёт `widget_instances`,
`widget_state` и три обязательных экземпляра. Установка CMS также использует
MigrationRunner, поэтому отдельный установщик виджетов не нужен.
Повторная миграция и повторное открытие редактора не создают дубликаты.
Для адресного обслуживания `MigrationRunner::run(null, ['20261011_create_widgets.sql'])`
применяет только перечисленные существующие миграции, с теми же блокировкой,
журналом и обновлением manifest. Зависимости других миграций остаются ответственностью
вызывающего кода; штатная команда CLI по-прежнему применяет все миграции.

Подключена только область `posts.sidebar` на `/posts` и `/posts/{slug}`.
Профиль, отдельные страницы категорий/архива, шапка, подвал и главное меню
не используют новую систему. В административной навигации добавлена только
ссылка на редактор. Пользовательские темы с собственными шаблонами сохраняют
свою разметку: для управления их блоками подключите область явно.

Источники исходной боковой панели:

- `themes/default/templates/posts.php`, `themes/default/templates/post.php`;
- совместимые старые представления `app/Views/themes/default/posts/index.php`
  и `app/Views/themes/default/posts/show.php`;
- данные `PostsController`, `Post::getSidebarData()`, `Category`;
- Bootstrap/Cartzilla из `public/assets/default/css/theme.min.css` и штатных
  скриптов темы. Существующий `#blogSidebar`, `offcanvas-lg`, мобильная кнопка,
  сетка, отступы и ссылки сохранены.

## Объекты API

Все классы находятся в `App\Widgets`, загрузка — штатная PSR-4 Composer.

| Объект | Ответственность |
| --- | --- |
| `WidgetInterface` | Контракт настроек, валидации и вывода |
| `AbstractWidget` | Валидация стандартных полей |
| `WidgetRegistry` | Типы, названия, разрешённые области, системный статус |
| `WidgetAreaRegistry` | Области, страницы, ограничения типов, обязательные слоты |
| `WidgetInstanceRepository` | Экземпляры, транзакции, порядок, видимость, версии |
| `WidgetContext` | Данные страницы, общие загрузчики, локализация, представление |
| `WidgetRenderer` | Условия вывода, обработка исключений, чистые буферы |
| `WidgetManager` | Регистрация ядра и инициализация расширений |

`widgets()` возвращает один менеджер на запрос. Инициализация ленивая,
после загрузки активных плагинов и до вывода виджетов. В `boot()` плагина
регистрируйте callback действия `fireball_widgets_register`; не вызывайте
`widgets()` до завершения загрузки остальных плагинов.

```php
add_action('fireball_widgets_register', function (
    \App\Widgets\WidgetRegistry $types,
    \App\Widgets\WidgetAreaRegistry $areas
): void {
    $types->register('my-plugin.notice', new MyNoticeWidget(), [
        'label' => 'my_plugin_notice_label',
        'areas' => ['posts.sidebar'],
        'system' => false,
    ]);
});
```

Идентификаторы: до 100 символов, первая буква строчная латинская, далее
буквы, цифры, точки, дефисы и подчёркивания. Используйте префикс плагина.
Повторная регистрация идентификатора вызывает `InvalidArgumentException`.
`doActionSafely()` из HookManager изолирует исключение одного callback
и продолжает регистрацию следующих плагинов.

## Контракт настроек

```php
interface WidgetInterface
{
    public function defaults(): array;
    public function fields(WidgetContext $context): array;
    public function validate(array $settings, WidgetContext $context): array;
    public function render(array $settings, WidgetContext $context): string;
}
```

Настройки и значения SQL считаются недоверенными. `validate()` возвращает
нормализованный массив либо бросает `InvalidArgumentException` с понятным
сообщением. Она вызывается при сохранении и при публичном выводе. Для своих
сложных типов можно реализовать контракт непосредственно; стандартный редактор
поддерживает следующие поля `AbstractWidget`:

| `type` | Параметры | Значение |
| --- | --- | --- |
| `text` | `label`, `max` (по умолчанию 150) | строка |
| `textarea`, `html` | `label`, `max` | строка |
| `number` | `label`, `min`, `max` | целое число в диапазоне |
| `checkbox` | `label` | boolean; валидатор также принимает 0/1 |
| `select` | `label`, `options` (`value => text`) | строковый ключ опции |
| `categories` | `label`, `options` (`slug => text`) | упорядоченный массив slug |
| `categories` + `multiple: true` | те же параметры | массив отмеченных slug |

`label` — ключ штатного перевода либо готовая строка. Тексты `options`
нужно перевести при формировании схемы. Для локализации плагин может вызвать
`FBL\Language::registerPluginLanguage()` как другие плагины CMS.
Настройки каждого экземпляра независимы; неизвестные поля стандартный
валидатор отбрасывает. После изменения схемы поддерживайте старые значения
или задавайте миграцию настроек. Схема предназначена для описания формы,
она не выполняет PHP из базы данных.

## Системные ограничения

В ядре зарегистрированы три обязательных слота:

| Ключ | Тип | Особенности |
| --- | --- | --- |
| `posts.categories` | `posts.categories` | всегда активен на обеих страницах |
| `posts.trending` | `posts.trending` | существующие шесть свежих записей; можно менять видимость по страницам |
| `posts.social` | `posts.social` | существующие социальные ссылки; пустой список не выводится |

Все три экземпляра нельзя удалить, отключить или перенести в другую область.
Их можно сортировать и менять заголовки. Категории дополнительно поддерживают
собственный порядок и скрытые slug. Общий порядок категорий в SQL не меняется.

Пример своего обязательного слота в зарегистрированной области:

```php
$types->register('my-plugin.navigation', new NavigationWidget(), [
    'label' => 'Navigation', 'areas' => ['my-plugin.sidebar'], 'system' => true,
]);
$areas->requireWidget(
    'my-plugin.main-navigation', 'my-plugin.navigation', 'my-plugin.sidebar',
    0, ['my-plugin.index']
);
```

Ограничения выводятся из PHP-регистрации. `system_key` — уникальная ссылка
на слот, а не изменяемый флаг разрешения. Репозиторий принудительно восстанавливает
тип, область, активность и обязательную видимость известных слотов даже при
повреждённых значениях SQL. Открытие редактора восстанавливает отсутствующий
обязательный экземпляр. Публичный запрос не создаёт таблицы и не записывает
виджеты: при недоступном хранилище выводятся обязательные значения по умолчанию.
Неизвестные системные ключи также нельзя удалить через редактор.

## Дополнительные области и вывод в теме

Регистрация сама по себе не меняет страницы сайта:

```php
$areas->register('my-plugin.sidebar', 'my_plugin_sidebar_label', [
    'my-plugin.index' => 'my_plugin_index_label',
    'my-plugin.show' => 'my_plugin_show_label',
], ['my-plugin.notice', 'my-plugin.navigation']); // [] разрешает все подходящие типы
```

Тип также должен разрешать область в `areas`; `['*']` разрешает любую
зарегистрированную область с подходящими ограничениями. В редакторе новая
область появляется автоматически, включая перенос между разрешёнными областями.

```php
$context = new \App\Widgets\WidgetContext('my-plugin.index', [
    'custom_data' => $data,
]);
echo render_widget_area('my-plugin.sidebar', $context);
```

Для публикаций контекст содержит `categories`, `trending_posts`, `post`,
`current_category`, `total_posts`, `posts_translation_prefix`. `get()` читает
данные; `once($key, $loader)` разделяет данные внутри одного контекста.
`posts()` переиспользует модель Post, `categories()` использует уже полученные
категории или один запрос к модели.
При выводе `instance` содержит метаданные текущего экземпляра. `forInstance()`
создаёт контекст с отдельными метаданными и общей памятью `once()`, поэтому
загрузчики страницы не выполняются заново для каждого виджета.

`WidgetContext::partial('categories', $data)` выводит
`partials/widgets/categories.php` через ThemeManager с обычным fallback тем.
Доступны переопределения встроенных partials `categories`, `post-list`, `social`,
`weather`, `weather-icon`, `html`. Контекст передаётся в partial автоматически.

## Адаптивность

Default-тема использует один DOM-блок внутри адаптивного Bootstrap offcanvas.
Параметры и запросы общие для компьютера и телефона, бизнес-логика не дублируется.
Если своей теме нужны два представления, создайте контексты `desktop`/`mobile`
с одинаковыми данными и используйте `partials/widgets/name.desktop.php` и
`partials/widgets/name.mobile.php`. Если такого файла нет, используется обычный
partial. Тяжёлые загрузчики держите в общем сервисе/кэше; не переносите SQL и
обращения к API в шаблоны. WeatherService уже общий на запрос и использует
одинаковые ключи кэша для обоих представлений.

## Кэширование и производительность

- Конфигурация читается одним запросом `widget_state LEFT JOIN widget_instances`
  и хранится в памяти менеджера на время запроса. Глобальный HTML-кэш отсутствует,
  чтобы пользовательские решения доступа и CSRF не попадали в общий кэш.
- Мутации блокируют строку `widget_state` транзакцией, проверяют `revision`,
  обновляют версию и сбрасывают снимок репозитория. Несвежая версия возвращает
  HTTP 409. Неполный порядок, дубликаты и запрещённые области возвращают 422.
- Новые свежие публикации выбираются моделью `Post::getWidgetLatestPosts()`:
  `is_published = 1`, дата не в будущем, JOIN категории, фильтр категории,
  исключение текущей записи. Исходные данные кэшируются на 60 секунд через
  существующий PostPublicCache; изменение записей инвалидирует его обычным
  механизмом CMS. Фильтр `public_posts_before_render` применяется пакетно и
  отдельно для текущего пользователя. Записи с запрещённым `subscription_access`
  пропускаются. Для одинаковых параметров внутри контекста список используется
  повторно. Отдельных SQL-запросов на каждую запись нет.
- WeatherService кэширует геокодирование на 30 дней, погоду на 15 минут,
  последние успешные данные на 6 часов, ошибки на 2 минуты. Ключ включает город,
  язык, единицы и дни, поэтому изменение настроек немедленно выбирает корректный
  кэш. Старые ключи истекают сами; очистка общего кэша CMS удаляет их. Локальная
  блокировка предотвращает одновременную загрузку одного прогноза.
- HTTP погоды: только фиксированные HTTPS-хосты Open-Meteo, проверка TLS,
  без переходов по редиректам, подключение до 1 секунды, каждый запрос до
  2,5 секунды, ответ до 256 KiB. При холодном кэше нужны геокодирование и прогноз.
  При ошибке посетитель получает последнее доступное значение или нейтральную
  карточку; внутренние подробности остаются в штатном приватном журнале.

В собственном виджете используйте `cache()` и ключи с префиксом плагина.
Включайте в ключ настройки, локаль, версию данных и необходимые параметры
контекста. Данные с зависимостью от пользователя кэшируйте только для конкретного
пользователя либо оставляйте в `WidgetContext::once()`. Для инвалидации доступны
`cache()->remove($key)` и собственные версии ключей. Не сохраняйте HTML с
токенами/пользовательскими разрешениями в общий кэш.

## Безопасность вывода

Виджет — доверенный PHP-код плагина. Строки настроек не должны становиться
именем PHP-файла, SQL-идентификатором, адресом произвольного HTTP-сервиса либо
аргументом `eval()`. Параметры SQL передавайте через штатный `db()->query()`.
Текст и HTML-атрибуты экранируйте `htmlSC()`, URL проверяйте и формируйте через
`base_href()`/существующие модели. `WidgetRenderer` изолирует исключения,
включая незакрытые output buffers; один неисправный виджет пропускается.
Фильтр `fireball_widget_html($html, $instance, $context)` доступен доверенным
плагинам для финальной обработки строки; исключение фильтра также изолируется.

«Произвольный HTML» одинаково ограничен для `admin` и `creator`. Он использует
штатный `sanitize_content_html()` и дополнительный пассивный allowlist:
текст, заголовки h2–h6, списки, ссылки, изображения, таблицы, code/pre и обычные
контейнеры. Разрешены классы оформления, title, безопасные href/src, alt,
размеры, параметры таблиц. Удаляются PHP processing instructions, скрипты,
формы, iframe, SVG/MathML, обработчики событий, style, id и data-атрибуты.
Очистка выполняется при сохранении и повторно при выводе; PHP никогда не
исполняется из настроек.

## Погода: город и геолокация

В настройках «Погоды» выберите **Город из настроек** либо
**Автоматически (геолокация)**. Существующие экземпляры остаются в ручном
режиме, пока администратор явно не изменит выбор. Поле города также задаёт
резервный прогноз для отказа в разрешении, тайм-аута и отсутствия геолокации.
Дополнительная миграция для этой настройки не нужна.

В автоматическом режиме страница сначала показывает резервный город.
При первом использовании посетитель нажимает «Погода рядом со мной» и разрешает
доступ в браузере. Если разрешение уже предоставлено, прогноз обновляется
автоматически. Отказ не вызывает повторные запросы разрешения при загрузке.
Определение позиции общее для всех погодных экземпляров на странице;
точный GPS не запрашивается, тайм-аут — 8 секунд. Требуется HTTPS либо доверенный
localhost; [правила браузерной геолокации](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition).

Координаты округляются до двух десятичных знаков на клиенте и сервере.
Точный адрес не определяется. В персональном прогнозе отображается
«Ваше местоположение»; обратное геокодирование названия населённого пункта
не выполняется. Геолокация не записывается в настройки экземпляра, PHP-сессию
или localStorage. Перед использованием посетителю показано, что приблизительные
координаты отправляются Open-Meteo.

`POST /widgets/weather/{id}` использует штатную CSRF-защиту и JSON с `latitude`,
`longitude`, `page`. Сервер проверяет границы координат, существование и активность
экземпляра, режим геолокации и видимость на странице. Единицы, дни и оформление
берутся из сохранённых настроек, а не из запроса посетителя. Есть штатный
RateLimiter: 30 запросов в минуту на IP, 300 в минуту суммарно. Ответ — серверный
partial и `Cache-Control: private, no-store`; он обновляет только содержимое
карточки. Кэш данных общий для одинаковой приблизительной позиции, языка,
единиц и дней, с теми же сроками и обработкой ошибок, что у прогноза по городу.
Для ошибок геолокации журнал не содержит trace с координатами.

Default-тема использует уже подключённый шрифт
[Cartzilla Icons](https://cartzilla-html.createx.studio/docs/icons.html): `ci-sun`,
`ci-moon`, `ci-cloud`, `ci-cloud-drizzle`, `ci-cloud-rain`, `ci-cloud-snow`,
`ci-cloud-lightning`, `ci-thermometer`. Отдельного fog-значка в пакете нет;
для тумана используется `ci-wind` с подписью «Туман». У прогнозных строк три
фиксированные колонки; значки 24×24 выровнены по общей вертикали, независимо
от длины температур. Emoji не используются.

Пользовательская тема может переопределить `weather`/`weather-icon`.
Если она выводит геолокацию в своей области, подключите
`/assets/default/js/widgets-weather.js` через обычный `footer_scripts`
и сохраните `data-weather-*` атрибуты карточки/внутреннего блока.

## Полный пример плагина

Создайте `plugins/widget-example/` с тремя файлами и установите/активируйте
плагин штатным интерфейсом CMS. Пример поддерживает несколько независимых
экземпляров и работает без изменения ядра или обязательного копирования
шаблона в тему.

`plugin.json`:

```json
{
  "slug": "widget-example",
  "name": "Пример виджета",
  "version": "1.0.0",
  "class": "FireballPluginWidgetExample",
  "description": "Информационные блоки через Widget API"
}
```

`Plugin.php`:

```php
<?php
use App\Widgets\AbstractWidget;
use App\Widgets\WidgetContext;
use App\Widgets\WidgetRegistry;
use App\Widgets\WidgetAreaRegistry;

final class FireballExampleNoticeWidget extends AbstractWidget
{
    public function defaults(): array
    {
        return ['title' => 'Объявление', 'message' => 'Добро пожаловать!'];
    }

    public function fields(WidgetContext $context): array
    {
        return [
            'title' => ['type' => 'text', 'label' => 'Заголовок', 'max' => 100],
            'message' => ['type' => 'textarea', 'label' => 'Сообщение', 'max' => 2000],
        ];
    }

    public function render(array $settings, WidgetContext $context): string
    {
        if (theme()->resolveFile('partials', 'widgets/example-notice') !== null) {
            return $context->partial('example-notice', compact('settings'));
        }
        $level = ob_get_level();
        ob_start();
        try {
            require __DIR__ . '/views/widget.php'; // Только фиксированный доверенный файл.
            return (string)ob_get_clean();
        } finally {
            while (ob_get_level() > $level) ob_end_clean();
        }
    }
}

final class FireballPluginWidgetExample implements \FBL\Plugins\PluginInterface
{
    public function install(): void {}
    public function uninstall(): void {}
    public function activate(): void {}
    public function deactivate(): void {}

    public function boot(): void
    {
        add_action('fireball_widgets_register', static function (
            WidgetRegistry $types, WidgetAreaRegistry $areas
        ): void {
            $types->register('widget-example.notice', new FireballExampleNoticeWidget(), [
                'label' => 'Информационный блок',
                'areas' => ['posts.sidebar'],
            ]);
        });
    }
}
```

`views/widget.php`:

```php
<section class="card rounded-4 mt-4">
    <div class="card-body p-4">
        <h4 class="h6"><?= htmlSC($settings['title']) ?></h4>
        <p class="mb-0 text-break"><?= nl2br(htmlSC($settings['message'])) ?></p>
    </div>
</section>
```

После активации тип «Информационный блок» появится в редакторе. Для изменения
внешнего вида скопируйте последний файл в
`themes/<ваша-тема>/partials/widgets/example-notice.php`. Для полноценной
локализации зарегистрируйте языковой каталог плагина и замените строки `label`
ключами переводов; стандартные подписи редактора уже доступны на ru/en/de/zh-cn.

Редактор использует компоненты и цветовые переменные административной панели
CMS: карточки, раскрываемые настройки, переключатели и встроенные Choices-списки.
После AJAX-сохранения списки создаются заново, а прежние экземпляры освобождают
обработчики событий. Несохранённые значения соседних форм остаются на месте.
На телефоне поля располагаются в одну колонку; на широком экране — в две.
Параметр поля `wide: true` позволяет растянуть короткое поле на всю ширину формы;
текст, HTML и группы категорий используют всю ширину по умолчанию.

## Проверки и текущие пределы

В `tests/` лежат самостоятельные PHP-проверки по принятому в проекте стилю
plugin-тестов. `sh tests/run-widgets.sh` поднимает частную MySQL с отключённой
TCP-сетью, выполняет полную миграцию CMS и проверки, затем останавливает сервер
и удаляет только свою директорию `tests/.tmp/widgets-*`. Можно указать путь к
mysqld переменной `MYSQLD_BIN`; нужны PDO MySQL, DOM и PHP 8.2+.
Детерминированные проверки не зависят от доступности внешнего погодного API.
Дополнительно предусмотрены HTTP/browser fixture и отдельная живая проверка API.

Редактор ограничивает общее число экземпляров сотней; свежие публикации —
1–20, прогноз — 1–7 дней, HTML — 50 000 символов. Геокодирование выбирает первый
результат для названия города: при неоднозначном названии уточняйте город
и страну. Погодная карточка использует встроенный набор Cartzilla Icons
и поддерживает обе цветовые темы.
Настройки сохраняются кнопкой экземпляра, порядок — сразу; несохранённые
формы сохраняют свои значения при добавлении/перемещении других виджетов.
Зависимости пользовательских плагинов от доступа должны возвращать решения
через существующий пакетный фильтр публикаций либо свой виджет.

Документация внешнего API: [прогноз Open-Meteo](https://open-meteo.com/en/docs),
[геокодирование](https://open-meteo.com/en/docs/geocoding-api).
