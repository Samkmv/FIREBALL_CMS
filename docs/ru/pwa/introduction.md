# PWA в FIREBALL CMS

PWA позволяет сайту работать как обычный сайт в браузере и как установленное приложение после добавления на главный экран устройства.

## Как включить

Откройте **Настройки → PWA**:

- включите PWA;
- при необходимости включите Push;
- задайте название приложения, короткое название, описание и цвета;
- укажите логотип и заставку, если они отличаются от favicon;
- сгенерируйте VAPID-ключи для Push.

Manifest и Service Worker создаются CMS автоматически. Темам не нужно добавлять отдельные файлы или скрипты.

## Иконка приложения

Manifest выбирает иконку в таком порядке:

1. favicon сайта;
2. логотип из настроек PWA;
3. стандартная иконка FIREBALL CMS.

CMS автоматически создаёт размеры 48, 72, 96, 128, 144, 152, 192, 384 и 512 пикселей, а также maskable icon для Android. При смене favicon или логотипа версия кэша обновляется.

## Установка приложения

На Android Chrome и совместимых браузерах можно использовать кнопку с атрибутом:

```html
<button data-pwa-install>Установить приложение</button>
```

На iPhone Safari нет события `beforeinstallprompt`. Пользователь должен открыть меню **Поделиться → На экран Домой**. CMS определяет iOS Safari и показывает подсказку только если сайт ещё не открыт как приложение.

Когда сайт открыт как приложение, CMS добавляет классы:

```css
body.pwa
body.standalone
html.pwa
html.standalone
```

Темы могут использовать их для safe-area, нижних панелей и скрытия кнопки установки.

## Push-уведомления

CMS использует Web Push + VAPID без сторонних сервисов. Разрешение на уведомления не запрашивается автоматически. Пользователь должен нажать кнопку:

```html
<button data-pwa-enable-push>Включить уведомления</button>
```

Для отключения:

```html
<button data-pwa-disable-push>Отключить уведомления</button>
```

На iPhone Push работает только для сайта, добавленного на главный экран и открытого с иконки.

## Счётчик на иконке PWA

Значок установленного приложения показывает количество непрочитанных из той же ленты, что и колокольчик на сайте. При открытом приложении счётчик синхронизируется при обновлении ленты, а в фоне — при получении Push. Когда непрочитанных нет, значок очищается. Открытие одного Push само по себе не помечает всю ленту прочитанной.

Возможности зависят от устройства:

- iPhone и iPad: требуется iOS/iPadOS 16.4 или новее, установка на экран «Домой» и разрешение на уведомления. Значки также должны быть разрешены в настройках ОС. См. [документацию WebKit](https://webkit.org/blog/14112/badging-for-home-screen-web-apps/).
- Компьютеры: числовой счётчик используется, если браузер и ОС поддерживают Badging API для установленного приложения.
- Android: системная точка на иконке связана с Push-уведомлениями. Её вид и наличие числа определяются оболочкой и настройками устройства; принудительно включить числовой счётчик через Badging API нельзя. См. [документацию Chrome](https://developer.chrome.com/docs/capabilities/web-apis/badging-api).

В неподдерживаемых браузерах остаётся счётчик у колокольчика внутри сайта. Если приложение закрыто, а нового Push нет, изменение количества на другом устройстве будет отражено при следующем открытии приложения или получении Push. Отдельные скрытые Push для синхронизации не отправляются.

Service Worker получает количество с сервера без кэширования и проверяет текущего пользователя перед показом Push. После выхода из аккаунта или при несовпадении получателя чужие уведомления не показываются. Разрешение на Push по-прежнему запрашивается только по нажатию пользователем кнопки.

После обновления сайта откройте PWA с подключением к сети, чтобы загрузился новый Service Worker. Проверки реализации без отправки реальных Push: `node tests/pwa_badge_unit.cjs`, `php tests/notification_center_unit.php`, `php tests/pwa_push_auth_regression.php`.

## NotificationService

Любой модуль или плагин должен создавать уведомления через единый сервис. CMS сначала сохранит уведомление внутри сайта, а затем автоматически отправит Web Push, если пользователь включил push и у него есть активная подписка браузера или PWA.

```php
use App\Services\NotificationService;

NotificationService::create([
    'user_id' => $userId,
    'title' => 'Новая заявка',
    'message' => 'Поступила новая заявка с сайта.',
    'type' => 'support_ticket',
    'action_url' => '/admin/contact-requests',
    'source' => 'support',
    'priority' => 'normal',
    'metadata' => [
        'request_id' => 123,
    ],
]);
```

Для плагинов также доступен helper `notification_create([...])`. Не отправляйте Web Push напрямую из плагина: push является дополнительным каналом доставки, которым управляет CMS.

Поддерживаются поля `user_id`, `title`, `message`, `type`, `action_url`, `icon`, `source`, `priority` и `metadata`. Старые вызовы `sendToUser()` продолжают работать и проходят через тот же поток уведомлений.

## Offline

Полный offline-режим пока не включён. Service Worker отдаёт страницу **Нет подключения** только для обычной навигации, если сеть недоступна.

Не кэшируются админка, авторизация, профиль, корзина, заказы, чат, уведомления и API с приватными данными.
