# FIREBALL CMS Editor 2.0 — аудит перед реализацией

Дата аудита: 30 июля 2026.

## Текущее состояние

- Основной редактор находится в `app/Modules/BlockEditor` и подключает один монолитный
  `public/assets/default/js/block-editor.js`.
- В браузере документ уже представлен массивом блоков, но обычная форма перед отправкой
  сериализует его в HTML. Поля `posts.content` и `pages.content` имеют тип `MEDIUMTEXT`.
- Старый HTML импортируется обратно в блоки. Скрытые блоки кодируются через `template`.
- Отдельные endpoints `/admin/block-editor/*` используют `BlockRepository` и ожидают JSON.
  Из-за этого они не видят блоки обычной HTML-записи и не совпадают с главным потоком сохранения.
- Публичный рендер поддерживает HTML и JSON, но JSON renderer покрывает не все существующие
  типы блоков.
- Формы записей и страниц используют один шаблон `admin/post_form.php`, стандартную оболочку
  админки, CSRF и отдельные autosave endpoints.
- Клиентская вставка очищает HTML, но вставляет его в текущий `contenteditable` через
  `execCommand`; разбиения большой статьи на блоки нет.
- История документа, мультивыбор, внутренний clipboard, slash-команды, command palette,
  локальное восстановление, outline и inspector отсутствуют.
- Файловый менеджер уже умеет picker-режим и безопасную загрузку через `SafeUploadService`.
- Расширения CMS используют `add_filter` / `apply_filters`, `add_action` / `do_action` и
  стандартный жизненный цикл плагина.
- Серверная очистка выполняется `sanitize_content_html`; опасные теги, обработчики и URL
  удаляются. Клиентская очистка остаётся обязательным первым слоем.

## Контракт совместимости

1. Существующие маршруты форм, autosave, preview и `/admin/block-editor/*` сохраняются.
2. Существующие события `fireball:post-editor-sync` и
   `fireball:post-editor-serialize` сохраняются.
3. Старый HTML и JSON продолжают открываться.
4. Основной сохраняемый формат остаётся публично совместимым HTML.
5. Точное состояние Editor 2.0 добавляется в HTML как невидимый versioned snapshot.
   При его отсутствии используется безопасный HTML-import.
6. Новые поля блока (`settings`, `meta`) необязательны.
7. Публичный renderer расширяется, но старый HTML не требует миграции.

## Риски и решения

- **Расхождение HTML/JSON:** repository научится читать snapshot из HTML; JSON остаётся
  допустимым для старых API.
- **Плагины:** типы блоков, config, assets и renderer получают фильтры; неизвестный блок
  не удаляется, а сохраняется как raw data.
- **Большие документы:** делегирование событий, частичное обновление активного блока,
  ограниченная история и отсутствие одного большого `contenteditable`.
- **Безопасность вставки:** DOM allowlist на клиенте плюс существующая серверная очистка.
- **Мобильные устройства:** панели превращаются в bottom sheets, toolbar прокручивается,
  drag имеет кнопочный fallback.
