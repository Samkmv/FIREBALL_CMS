# Обновления при работающем плеере — FIREBALL CMS 1.8.19

Исправление поставляется с Tape Room 1.7.10 и темой 1.3.2. Оно устраняет ожидание завершения всех прослушиваний перед обновлением CMS. Увеличение тайм-аута и удаление файлов блокировок не требуются.

## Причина

Ранее каждый PHP-запрос удерживал общую блокировку `storage/update.lock` до завершения. Это защищало исходники и базу при обновлении, но аудио с устройства или Google Drive могло передаваться несколько минут. Закрытая вкладка тоже не гарантировала немедленного завершения передачи на сервере. Обновлятор ждал 30 секунд и безопасно отменял установку.

## Как работает исправление

- Контроллер проверяет доступ к песне, загружает необходимые классы и подготавливает источник под обычной блокировкой.
- Перед длинной передачей `UpdateLock::stream()` закрывает сессию и соединение с базой, проверяет отсутствие активной транзакции, затем освобождает блокировку читателя. Передача становится завершающей операцией запроса. Дальше разрешены только уже загруженный код, открытый файл, cURL и защищённые runtime-каталоги. Повторное обращение к базе запрещено.
- Локальная музыка передаётся из заранее открытого файла. Drive использует предварительно загруженные `GoogleDrive`, `DriveStream`, `DriveCache`, `MediaStorage`; кэш и учётные данные находятся в сохраняемом `storage/`.
- Длинные запросы чата, которые читают базу, сохраняют блокировку до выхода, но завершаются при появлении намерения обновления. Изменения данных и остальные запросы по-прежнему должны завершиться до замены кода.
- Новые запросы во время обновления получают HTTP 503 с `X-Fireball-Maintenance: 1` и `Retry-After`. Tape Room ожидает доступности сайта и повторяет загрузку с прежней позиции. Ожидание обслуживания ограничено 30 минутами и отменяется паузой, сменой песни или окончательной ошибкой доступа. Браузер может потребовать повторного нажатия Play.

Резервирование кода и БД, проверка Git, согласование зависимостей, миграции и восстановление сохраняются. Пользовательский PHP-код не объявляется безопасным автоматически. Нельзя освобождать блокировку у произвольного запроса, который продолжает работать с базой.

## Обычная установка

После публикации версии 1.8.19 в `Samkmv/FIREBALL_CMS`, ветка `main`, выполнить проверку и обновление через админку. Если Tape Room обновлялся независимо через раздел плагинов, затем обновить его отдельно до 1.7.10: обновление движка сохраняет такие пакеты. Плагин 1.7.10 требует CMS 1.8.19, поэтому порядок — сначала движок, затем плагин.

Уже начавшаяся передача на исправленной версии может завершиться во время установки. Новый Range-запрос или переход на следующую песню во время обслуживания ожидает его завершения в обновлённом плеере. Не требуется просить слушателей закрывать страницы.

## Однократный переход со старой версии, если обновление уже заблокировано

Старый выполняющийся PHP-запрос не может получить исправление посреди передачи. Если такие запросы удерживают блокировку, нужен однократный перезапуск PHP через панель хостинга. Он может кратковременно прервать звук; старые открытые вкладки могут потребовать повторного нажатия Play или перезагрузки страницы.

После публикации исправления в `main`:

1. Создать резервную копию файлов сайта и БД средствами хостинга. Убедиться, что её можно восстановить.
2. Временно ограничить публичный доступ к сайту средствами хостинга, сохранив себе доступ к админке, например по своему IP. Ограничение оставить до завершения обоих обновлений. Не удалять `storage/update.lock` или `storage/update.maintenance`.
3. Из одного официального архива исправления заменить перечисленные ниже шесть файлов движка. При собственных правках в них сначала сравнить и сохранить изменения; не перезаписывать их вслепую. Файлы плагина вручную не заменять: это нарушит проверку целостности независимо установленного пакета.
4. Перезапустить PHP в панели хостинга, чтобы завершить старые запросы и сбросить старый код в OPcache.
5. В админке выбрать канал `main`, проверить обновления и установить полный релиз CMS 1.8.19. Затем в разделе плагинов обновить Tape Room до 1.7.10, если он был сохранён как независимый пакет. Номера версии и служебные записи плагинов вручную не изменять.
6. Открыть публичный доступ после успешного завершения обновлений.

Файлы для первоначального исправления:

```
app/Services/UpdateCenter.php
app/Services/ChatRealtimeService.php
app/Services/GroupChatRealtimeService.php
core/Database.php
core/UpdateLock.php
public/runtime-gate.php
```

Обновлятор признаёт эти предварительно заменённые файлы штатными только при побайтовом совпадении с полученным `origin/main`. Перед согласованием с Git они резервируются. Символические ссылки и любые отличия остаются конфликтами. До публикации соответствующего кода в `main` локальная сборка не может пройти эту проверку. Архив не должен содержать `config.local.php`, загрузки, музыку, БД или зависимости.

Если уже отмечена незавершённая установка, сначала использовать штатное восстановление из [инструкции миграции](updater-1.8.13-migration.md). Перезапуск PHP не заменяет восстановление.

## Проверки

```
php tests/update_streaming.php
php tests/update_center_git.php
php tests/update_center_dependencies.php
php tests/update_center_runtime.php
php tests/update_center_recovery.php
node tests/tape_room_media_recovery.cjs
```

Проверка потоков запускает отдельные PHP-процессы с медленным получателем: локальный файл, Range и кэш Drive. Во время передачи обновлятор получает исключительную блокировку, исходники потока заменяются тестовым кодом, новые запросы блокируются шлюзом, а начатая передача завершается без искажения байтов и без последующей автозагрузки. Отдельно проверяются сохранение блокировки обычного запроса, завершение длинного опроса, запрет одновременных обновлений и активной транзакции.

Проверка восстановления использует новую временную MySQL-базу, локальный Composer-пакет и тестовые Git-репозитории. Рабочие музыка и БД не используются. Все временные файлы находятся в отдельных каталогах `tests/.tmp/`, отчёты — в `tests/artifacts/`.
