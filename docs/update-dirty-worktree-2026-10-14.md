# Обновление заблокировано локальными изменениями

> Обновление 16.10.2026: Composer-файлы и документация компонентов теперь обрабатываются автоматически с резервной копией. См. [новую инструкцию](update-composer-2026-10-16.md). Команды ниже относятся к старым установленным обновляторам.

Красное сообщение означает, что файлы установки отличаются от текущего Git-коммита. Отдельное обновление Tape Room меняет `plugins/reel-player`, а Composer может менять отслеживаемые файлы `vendor`. Это не означает повреждение базы или музыки. Игнорирование этих каталогов без сохранения может скрыть реальные правки и не предотвращает конфликт при Git-обновлении.

Зелёное сообщение «Установлена актуальная версия» описывает сравнение коммитов с выбранной удалённой веткой. Локальные изменения файлов проверяются отдельно, поэтому оба сообщения могут показываться одновременно. Если удалённая ветка действительно совпадает с установленным коммитом, нового обновления CMS ещё нет.

## Диагностика на сервере

Откройте SSH в корневой папке нужной установки CMS (с `config`, `app`, `plugins`, `vendor` и `.git`) и выполните:

```sh
git rev-parse --show-toplevel
git status --short
git diff --stat
git diff --cached --stat
```

Эти команды ничего не изменяют. Проверьте полный список: красная карточка показывает только первые пять путей. Если изменены также `composer.json`, `composer.lock`, файлы ядра или другие плагины, сначала разберите их отдельно.

## Сохранение перед доступным обновлением

Сделайте внешнюю резервную копию текущих файлов и БД через панель хостинга. На время смены кода остановите публичный трафик и фоновые задания средствами хостинга; оставьте себе административный доступ для запуска штатного обновления. Не включайте вручную `storage/update.maintenance`: этот внутренний маркер блокирует загрузку приложения.

Если проверка показала, что мешают именно `plugins/reel-player` и `vendor`, можно сохранить их отслеживаемые и новые файлы в отдельный Git stash:

```sh
git stash push --include-untracked -m "FIREBALL before CMS update 2026-10-14" -- plugins/reel-player vendor
git stash list -1
git status --short
```

Это заменяет код этих двух каталогов его состоянием из установленного коммита. Поэтому выполняйте этот шаг во время обслуживания непосредственно перед доступным обновлением. Остальные каталоги, конфигурация, загрузки и музыкальное хранилище не входят в команду. Новый stash сохраняет правки и новые файлы; его не следует удалять до завершения проверки сайта.

После этого выполните штатное обновление CMS в админке. Если осталось другое блокирующее изменение, не применяйте общий `reset --hard` или `git clean` для обхода ошибки. Если сервер сообщает, что обновление уже установлено, не подменяйте код только ради исчезновения предупреждения.

После успеха проверьте сайт и версию Tape Room до возвращения трафика. Не применяйте старый stash поверх новой версии автоматически: это вернёт старые файлы и может отменить исправления. При необходимости изучите сохранённые правки командой `git stash show --stat 'stash@{0}'` и перенесите только нужные изменения. При сбое после изменения установки используйте штатное восстановление кода и БД по [инструкции развёртывания](deployment/README.md#восстановление-после-ошибки), сохраняя внешний снимок исходной рабочей установки.

## Исправления диагностики и карточек

Обновлятор теперь читает `git status --porcelain=v1 -z`, сохраняя сырые байты команды. Первый символ пути больше не теряется; пробелы, Unicode и переименования не разбираются как обычный текст. При переименовании проверяются оба пути. Ошибка или неполный вывод Git не считается чистой установкой.

Карточки центра обновлений используют сжимаемые колонки, а длинные пути переносятся внутри предупреждения. На ширинах 320, 390 и 1280 px горизонтальное переполнение не выявлено; проверены светлая и тёмная темы. Наличие реальных локальных изменений по-прежнему блокирует обновление.

Проверки: `php tests/update_center_git.php`; браузерный стенд `tests/update_center_preview.php`. Все временные данные находятся под `tests/.tmp/`, результаты — `tests/artifacts/update-center/`. Боевой сервер в этих проверках не использовался.
