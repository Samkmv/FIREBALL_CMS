# Иконка установки PWA на iPhone

## Причина и границы диагностики

20 октября 2026 выполнена проверка публичного maxipapa.ru без cookies, с User-Agent iPhone. HTML содержал один корректный `apple-touch-icon` со ссылкой на `/uploads/pwa/apple-touch-icon.png?v=…`. Эта ссылка и оба корневых Apple-адреса отдавали **одинаковый PNG 180×180**, 200 `image/png`, без перенаправлений и ошибок CRC. Манифест и его PNG 192/512 также доступны. Корневой ответ уже имел ETag по содержимому и обязательную ревалидацию; статический uploads-адрес — месячный immutable-кэш. CSP, блокирующей изображения, не обнаружено.

Таким образом, серверный 404, неверный MIME и отсутствие подходящей картинки не объясняют наблюдение пользователя. Уязвимое место прежней реализации: установщик мог получить предпочтительную Apple-иконку **только отдельным сетевым запросом**. Доступность файла в Safari не подтверждает работу загрузчика системного окна установки.

По документации [WebKit](https://webkit.org/blog/13878/), `apple-touch-icon` имеет приоритет над иконками манифеста; монограмма используется как запасная картинка. В [первичном сообщении разработчиков об iOS 27.2](https://www.reddit.com/r/PWA/comments/1wsruwy/pwa_icon_not_working_on_ios_272beta2/) описаны сравнительные тесты: сетевые PNG дают монограмму, тот же PNG в `data:` работает. Это независимые наблюдения, **не официальное подтверждение Apple** и не проверка конкретного iPhone владельца maxipapa.ru.

Наиболее вероятная первопричина — сбой отдельной загрузки иконки установщиком iOS 27.x. Исправление устраняет эту сетевую зависимость, а не требует очистки кэша. Окончательное подтверждение причины на конкретном устройстве требует повторной установки после выкладки.

## Реализация

- Общий `pwa_head_tags()` сразу выдаёт один `apple-touch-icon` 180×180 с `data:image/png;base64,…`. JavaScript, определение User-Agent и дополнительная загрузка картинки не нужны. Стандартная тема и Tape Room используют один механизм.
- Изображение берётся из уже выбранного CMS набора: пользовательские, старые плоские, migrated/generated иконки и оформление темы сохраняются. Приоритет favicon / PWA-настроек этим исправлением не меняется.
- Один `appleTouchIconPng()` обслуживает встраивание и публичные GET/HEAD `/apple-touch-icon.png` и `/apple-touch-icon-precomposed.png`. При наличии GD PNG перекодируется в непрозрачный RGB на фоне `pwa_background_color`, без перезаписи исходников и без генерации файлов на запросах страниц.
- Встраивание ограничено **128 KiB исходного PNG**; для большего изображения остаётся HTTP-адрес. Источник ограничен 4 MiB и размером 180×180. Битые PNG не выдаются как успешное изображение. Без GD сохраняется поддержка готовых PNG.
- Запасной HTTP-адрес версионируется SHA-256 фактического канонического изображения. ETag и Content-Length соответствуют именно выдаваемым байтам; смена логотипа или фона обновляет изображение, URL и ETag. Корневые ответы ревалидируются и не попадают в статический кэш service worker.
- В манифест добавлен HTTP PNG 180×180 `purpose:any`; существующие HTTP PNG 192/512 и maskable 512 для Android не заменяются Base64 и не изменяются.
- При известной приложению CSP, запрещающей `data:` для изображений, HTML использует сетевой fallback. Политики безопасности не ослабляются. Если CSP задаётся внешним сервером/CDN или метатегом темы, для встраивания требуется разрешить `data:` в `img-src`; PHP не может достоверно увидеть такие внешние политики.

## Регрессионные проверки

`python3 tests/pwa_installation_check.py` запускает реальные роутер, контроллер и helpers в отдельной установке с SQLite: 37 проверок. Проверяется декодирование встроенного PNG без HTTP-запроса изображения, совпадение с корневым ответом, непрозрачность и сохранение пикселей логотипа, оба шаблона, старые наборы, смена настроек и ETag, GET/HEAD/304, CSP, лимит HTML, битые файлы, отсутствие изменения системных иконок и HTTP-ресурсы Android.

`php tests/update_center_runtime.php`: 51 проверка генерации, размеров манифеста, миграции и сохранности пользовательских иконок при обновлениях. Все временные данные находятся в `tests/.tmp/` и удаляются после завершения; отчёты — в `tests/artifacts/`.

Эти тесты **не эмулируют системное окно iOS 27.2** и не заменяют проверку на физическом устройстве. Боевой сайт при разработке только читался, изменений его настроек или файлов не выполнялось.

## Приёмка на iPhone после выкладки

1. Убедиться в исходном HTML страницы, что единственный `apple-touch-icon` 180×180 содержит `data:image/png;base64,`, а манифест по-прежнему содержит обычные PNG-адреса.
2. Открыть страницу в Safari, затем «Поделиться → На экран Домой»: проверить логотип уже в окне предварительного просмотра.
3. Сохранить новую иконку и запустить приложение. Старый установленный ярлык может хранить снимок прежней иконки — автоматическая замена уже сохранённого ярлыка не обещается. Очистка данных сайта для исправления не требуется.
4. Проверить установку на Android: имя, стартовая страница, PNG 192/512 и maskable-иконка остаются прежними.
