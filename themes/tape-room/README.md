# Tape Room

Самостоятельная тема FIREBALL CMS. Главная страница — экран аудиоплеера Tape Room с навигацией сайта. Исходная разметка плеера находится в `partials/player.php`, его стили, скрипты, иллюстрации и шрифт — в `assets/`. Тема не наследует шаблоны, фрагменты и ресурсы Default (`inheritDefault: false`).

Для работы нужен активный плагин `reel-player`: он хранит коллекции и обслуживает защищённые API и аудио. Активируйте тему Tape Room в **Админка → Темы**. Поле `homepage: "home"` в манифесте закрепляет плеер на корне сайта независимо от обычной настройки главной страницы. Гости могут просматривать одобренный каталог и слушать музыку; после входа, регистрации и подтверждения 2FA пользователь попадает на главную.

`/admin/reel-player` показывает обзор, статистику пользователей, отправленные альбомы и модерацию; `/admin/reel-player/genres` — библиотеку жанров. Рабочие запросы плеера используют `/tape-room/api`, аудио и обложки — `/tape-room/media` и `/tape-room/catalog`. Просмотр одобренного каталога и потоковое прослушивание доступны без входа. Добавление, редактирование и личные коллекции требуют регистрации. Личные записи и коллекции по-прежнему проверяются по владельцу; пользователь отправляет собственный альбом на модерацию. Администратор или создатель одобряет / отклоняет его; в общем каталоге появляются только одобренные альбомы. Собственные альбомы администратора и создателя публикуются без самопроверки; черновик становится общедоступным только после явной публикации. Глобальные настройки Google доступны создателю сайта.

Ранее зарегистрированный адрес Google OAuth `/admin/reel-player/drive/callback` сохранён и требует входа без административной роли. После подключения Google возвращает пользователя на главную страницу. Старые административные API и адреса ресурсов сохранены для уже открытых вкладок.

Страницы входа, регистрации, восстановления доступа, аккаунта, обычной CMS-страницы и публикации оформлены собственными шаблонами. Для пока отсутствующих шаблонов используется собственная страница 404.

Жанры доступны в редакторах альбомов и песен, с поиском по библиотеке. Раздел жанра учитывает собственную музыку и одобренный каталог; чужие черновики туда не попадают. На главной странице рядом с названием показана метка «Бета» в цветах выбранной темы.

## Интерфейс сайта и Bootstrap

Bootstrap **5.3.8** размещён локально в `assets/bootstrap/`, включая JS bundle с Popper и лицензию MIT. CDN при работе сайта не используется. Структура navbar/offcanvas взята за основу из Default, оформление и ресурсы принадлежат Tape Room.

Навигация и боковое меню находятся в `partials/navbar.php`, формы входа и регистрации — в `templates/auth/`. Цвета, типографика и оформление компонентов задаются в `assets/css/shell.css`, поведение оболочки — в `assets/js/shell.js`. Переключение светлой и тёмной темы синхронизировано с плеером.

Все иконки интерфейса сайта и плеера используют локальный Cartzilla Icons в `assets/icons/`; общая карта ролей задана в `includes/icon-map.php`. Navbar содержит общую кнопку «Аккаунт» с Bootstrap dropdown: для гостя — «Войти» и «Регистрация», для вошедшего пользователя — профиль, настройки и выход с CSRF-защитой. Примеры используемых иконок доступны в `/tape-room/ui-kit#icons`. Кнопки play/pause выровнены внутри круглых элементов. Кнопки в списках имеют отступы по 14 px от краёв строки; hover меняет фон, цвет иконки и тень без изменения размеров. Полоса воспроизведения занимает всю ширину своего блока и раздельно показывает пройденный участок и буфер. Поиск оформлен общей группой ввода с иконкой слева. SVG-иллюстрации катушек и декор плеера сохранены.

`/tape-room/ui-kit` — библиотека всех семейств компонентов Bootstrap: accordion, alerts, badges, breadcrumbs, buttons, button groups, cards, carousel, close button, collapse, dropdowns, list groups, modal, navbar, navs/tabs, offcanvas, pagination, placeholders, popovers, progress, scrollspy, spinners, toasts и tooltips, а также всех типов полей, сетки, таблиц и типографики. Раздел «Элементы плеера» показывает круглые play/pause, состояния избранного, песню в списке и скруглённую обложку. Она доступна администратору и создателю через боковое меню. Создателю показана ссылка на штатный редактор файлов темы. Демонстрационные формы не отправляют данные на сервер.

Для изоляции стилей подключается `bootstrap.scoped.css`: правила Bootstrap действуют внутри `.tr-bootstrap`. Исключение — фон модального окна, который Bootstrap добавляет в `body`. Библиотека и личные ленты перенесены в боковое меню, область песен и альбомов под плеером занимает всю ширину. `includes/player-shell.php` подставляет navbar в существующее место заголовка; действия разделов каталога передаются прежним обработчикам без перезагрузки страницы и остановки музыки. Окна плеера используют Bootstrap Modal, сортировка — Dropdown, уведомления — Toast. Общие элементы оформлены в палитре Tape Room; аудиоэлемент, очереди и катушки сохраняют свой жизненный цикл. Заголовок бокового меню — «Навигация», типографика и интервалы компактные.

После замены версии Bootstrap пересоберите изолированный CSS из корня проекта: `python3 tools/build-tape-room-bootstrap.py` (зависимость для сборки: `tinycss2==1.4.0`). На сервере Python и эта зависимость не нужны. Происхождение и контрольные суммы библиотеки указаны в `assets/bootstrap/README.md`.

## Torrent в браузере

Список песен сортируется естественно по пути и номеру в имени файла; исходный индекс файла внутри torrent сохраняется. Кнопка выбора файла использует общий Bootstrap-компонент темы, тот же образец размещён в UI-библиотеке.

В боковом меню откройте **Музыка из torrent**, выберите `.torrent` (до 2 МБ), песни и название альбома. Альбом появится в «Моя музыка». Используется локальный WebTorrent 3.0.21. Музыка передаётся прямо в браузер через WebRTC или web seed: PHP не принимает аудио, не проксирует поток и не сохраняет его на диск. Обычные TCP/uTP-пиры браузеру недоступны; раздача должна иметь WebRTC-пиров или web seed с CORS. Нужен HTTPS либо localhost, WebRTC и Service Worker. Формат аудио должен поддерживаться самим браузером.

IndexedDB хранит метаинформацию `.torrent`, выбранные песни, теги, жанр, обложки и избранное отдельно для аккаунта на этом устройстве. Аудиоблоков в IndexedDB, Cache Storage или на сервере нет: для них задан только MemoryStore. Лимита 128 МБ на песню больше нет. Выбираются только запрошенные диапазоны; при переключении песни или остановке torrent его буфер освобождается. При заполнении буфера удаляются наименее недавно использованные блоки с пометкой WebTorrent для повторного получения при перемотке. Это использует адаптер `_markUnverified` закреплённой версии WebTorrent 3.0.21; при смене библиотеки нужно повторить проверку потока и перемотки. Ограничения: до 50 раздач, 1000 файлов в раздаче, блок до 16 МБ, буфер до 192 МБ. Закрытие страницы прекращает сеанс.

`music-metadata` 12.2.1 читает теги, длительность и встроенную обложку непосредственно из диапазонов torrent. Чтение ограничено 4 МБ и 25 секундами. Отсутствие тегов не блокирует воспроизведение; длительность также уточняет аудиоэлемент. Такие альбомы остаются в библиотеке браузера и не отправляются на модерацию или в общий каталог.

`/tape-room/torrent-worker.js` объединяет браузерную передачу диапазонов с обычным CMS PWA worker. Поток `/webtorrent/…` адресован конкретной вкладке через MessagePort, поддерживает Range и `no-store`; он не идёт на HTTP-сервер и не использует общий кэш. Остальная обработка PWA сохраняется.

### Как подготовить раздачу

1. На компьютере раздающего откройте WebTorrent Desktop с официального https://webtorrent.io/desktop/, добавьте тот же torrent и обеспечьте наличие всех его исходных файлов. Оставьте приложение раздавать музыку.
2. У раздающего и браузера должен быть общий WebSocket-трекер `wss://…`. Добавление трекера не создаёт раздающих: музыка должна реально находиться у совместимого WebRTC-пира. Доступность публичных трекеров меняется; используйте работающий трекер своей раздачи.
3. В Tape Room войдите в аккаунт, откройте **Музыка из torrent**, выберите `.torrent` и песни, добавьте альбом. Запустите его из **Моя музыка**. Порт CMS для torrent открывать не требуется; сайт на боевом домене должен использовать HTTPS.
4. Если пиров нет, проверьте, что раздача та же (тот же info hash), раздающий онлайн, трекер доступен и сеть не блокирует WebRTC. Обычные раздающие, поддерживающие только TCP/uTP, не подключаются к браузеру напрямую.

Второй способ — web seed в `.torrent`: прямые HTTPS-адреса исходных файлов с правильной структурой путей, поддержкой `Range`/ответов `206` и CORS для домена сайта. Этот источник обращается прямо к браузеру; музыка не проходит через PHP или диск CMS. Если нет ни WebRTC-пира, ни web seed, воспроизведение в режиме «только браузер» невозможно. Справка доступна также внутри окна torrent на сайте.

Проверено потоковое воспроизведение и перемотка через web seed, с буфером в памяти браузера. Отдельная интеграционная проверка закреплённой библиотеки читает WAV размером 172 800 044 байта с буфером 256 КиБ: начало, дальний участок и снова начало после освобождения блоков. Это проверка передачи диапазонов и повторного получения данных, а не декодирования большого файла аудиоэлементом. Соединение с WebRTC-пиром в тестовом встроенном браузере не было подтверждено. Официальное описание ограничений: https://webtorrent.io/faq.

Перед подключением показывается количество доступных браузеру WebRTC-трекеров и web seeds. Для закрытой раздачи публичный трекер не подставляется. Ошибки отсутствия аудиоформатов, источников, поступивших данных и ошибки кодека различаются. `assets/js/browser-compat.js` предоставляет отсутствующие в старых браузерах `Uint8Array.toBase64`, `toHex` и `fromHex` до запуска WebTorrent.
