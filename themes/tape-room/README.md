# Tape Room

Самостоятельная тема FIREBALL CMS. Главная страница — экран аудиоплеера Tape Room с навигацией сайта. Исходная разметка плеера находится в `partials/player.php`, его стили, скрипты, иллюстрации и шрифт — в `assets/`. Тема не наследует шаблоны, фрагменты и ресурсы Default (`inheritDefault: false`).

Для работы нужен активный плагин `reel-player`: он хранит коллекции и обслуживает защищённые API и аудио. Активируйте тему Tape Room в **Админка → Темы**. Поле `homepage: "home"` в манифесте закрепляет плеер на корне сайта независимо от обычной настройки главной страницы. Гость перенаправляется на собственную страницу входа темы; после входа, регистрации и подтверждения 2FA пользователь попадает на главную.

`/admin/reel-player` показывает обзор, статистику пользователей, отправленные альбомы и модерацию; `/admin/reel-player/genres` — библиотеку жанров. Рабочие запросы плеера используют `/tape-room/api`, аудио и обложки — `/tape-room/media` и `/tape-room/catalog`. Доступ имеют все вошедшие пользователи. Личные записи и коллекции по-прежнему проверяются по владельцу; пользователь отправляет собственный альбом на модерацию. Администратор или создатель одобряет / отклоняет его; в общем каталоге появляются только одобренные альбомы. Глобальные настройки Google доступны создателю сайта.

Ранее зарегистрированный адрес Google OAuth `/admin/reel-player/drive/callback` сохранён и требует входа без административной роли. После подключения Google возвращает пользователя на главную страницу. Старые административные API и адреса ресурсов сохранены для уже открытых вкладок.

Страницы входа, регистрации, восстановления доступа, аккаунта, обычной CMS-страницы и публикации оформлены собственными шаблонами. Для пока отсутствующих шаблонов используется собственная страница 404.

Жанры доступны в редакторах альбомов и песен, с поиском по библиотеке. Раздел жанра учитывает собственную музыку и одобренный каталог; чужие черновики туда не попадают. На главной странице рядом с названием показана метка «Бета» в цветах выбранной темы.

## Интерфейс сайта и Bootstrap

Bootstrap **5.3.8** размещён локально в `assets/bootstrap/`, включая JS bundle с Popper и лицензию MIT. CDN при работе сайта не используется. Структура navbar/offcanvas взята за основу из Default, оформление и ресурсы принадлежат Tape Room.

Навигация и боковое меню находятся в `partials/navbar.php`, формы входа и регистрации — в `templates/auth/`. Цвета, типографика и оформление компонентов задаются в `assets/css/shell.css`, поведение оболочки — в `assets/js/shell.js`. Переключение светлой и тёмной темы синхронизировано с плеером.

Все иконки интерфейса сайта и плеера используют локальный Cartzilla Icons в `assets/icons/`; общая карта ролей задана в `includes/icon-map.php`. Navbar содержит общую кнопку «Аккаунт» с Bootstrap dropdown: для гостя — «Войти» и «Регистрация», для вошедшего пользователя — профиль, настройки и выход с CSRF-защитой. Примеры используемых иконок доступны в `/tape-room/ui-kit#icons`. Кнопки play/pause выровнены внутри круглых элементов. SVG-иллюстрации катушек и декор плеера сохранены.

`/tape-room/ui-kit` — библиотека палитры, кнопок, форм, адаптивной сетки, модального окна, бокового меню, вкладок, accordion и уведомлений. Она доступна администратору и создателю через боковое меню. Создателю показана ссылка на штатный редактор файлов темы. Демонстрационные формы не отправляют данные на сервер.

Для изоляции стилей подключается `bootstrap.scoped.css`: правила Bootstrap действуют внутри `.tr-bootstrap`. Исключение — фон модального окна, который Bootstrap добавляет в `body`. Библиотека и личные ленты перенесены в боковое меню, область песен и альбомов под плеером занимает всю ширину. `includes/player-shell.php` подставляет navbar в существующее место заголовка; действия разделов каталога передаются прежним обработчикам без перезагрузки страницы и остановки музыки. Собственные окна плеера сохранены. Заголовок бокового меню — «Навигация», типографика и интервалы компактные.

После замены версии Bootstrap пересоберите изолированный CSS из корня проекта: `python3 tools/build-tape-room-bootstrap.py` (зависимость для сборки: `tinycss2==1.4.0`). На сервере Python и эта зависимость не нужны. Происхождение и контрольные суммы библиотеки указаны в `assets/bootstrap/README.md`.

## Torrent в браузере

В боковом меню откройте **Музыка из torrent**, выберите `.torrent` (до 2 МБ), песни и название альбома. Альбом появится в «Моя музыка». Используется локальный WebTorrent 3.0.21. Музыка передаётся прямо в браузер через WebRTC или web seed: PHP не принимает аудио, не проксирует поток и не сохраняет его на диск. Обычные TCP/uTP-пиры браузеру недоступны; раздача должна иметь WebRTC-пиров или web seed с CORS. Нужен HTTPS либо localhost, WebRTC и Service Worker. Формат аудио должен поддерживаться самим браузером.

IndexedDB хранит метаинформацию `.torrent`, выбранные песни, теги, жанр, обложки и избранное отдельно для аккаунта на этом устройстве. Аудиоблоков в IndexedDB, Cache Storage или на сервере нет: для них задан только MemoryStore. Выбираются только запрошенные диапазоны; при переключении песни или остановке torrent его буфер освобождается. Ограничения: до 50 раздач, 1000 файлов в раздаче, 128 МБ на песню, блок до 4 МБ, буфер до 192 МБ. Закрытие страницы прекращает сеанс.

`music-metadata` 12.2.1 читает теги, длительность и встроенную обложку непосредственно из диапазонов torrent. Чтение ограничено 4 МБ и 25 секундами. Отсутствие тегов не блокирует воспроизведение; длительность также уточняет аудиоэлемент. Такие альбомы остаются в библиотеке браузера и не отправляются на модерацию или в общий каталог.

`/tape-room/torrent-worker.js` объединяет браузерную передачу диапазонов с обычным CMS PWA worker. Поток `/webtorrent/…` адресован конкретной вкладке через MessagePort, поддерживает Range и `no-store`; он не идёт на HTTP-сервер и не использует общий кэш. Остальная обработка PWA сохраняется.
