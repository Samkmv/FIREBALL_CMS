# Tape Room: аудит серверной части

Дата: 11 октября 2026. Проверены службы GoogleDrive, DriveCache, DriveStream, MediaStorage, библиотека Library, контроллер PlayerController и маршруты.

## Исправленные ошибки

1. **Обновление токена могло восстановить отключённый аккаунт.** Отключение, запись результата OAuth и обработка 401 теперь используют ту же приватную блокировку аккаунта, что обновление токена. Ответ 401 от старого запроса не отменяет более новый токен.
2. **Поздний OAuth callback из другой сессии мог восстановить отменённое подключение.** Отключение меняет сохраняемую метку аккаунта. Pending OAuth привязан к этой метке; callback проверяет её до обмена кода и повторно под блокировкой перед записью. Новый явно начатый вход после отключения использует новую метку. Метка не является токеном и не считается подключением.
3. **Смена Client ID при пустом Client Secret переиспользовала секрет другого OAuth клиента.** Такой запрос отклоняется до изменения рабочих настроек; повторное сохранение прежнего Client ID с пустым Secret сохраняет действующий секрет.
4. **Одновременный импорт одной песни Drive давал ошибку уникального ключа.** Импорт использует атомарный MySQL upsert и возвращает существующий ID. Повторное добавление сохраняет пользовательское название, длительность, избранное и обложку; членство плейлиста не дублируется.
5. **Очистка кэша могла разорвать общую блокировку загрузок.** Удаление старого файла блокировки было небезопасно для уже открытого дескриптора другого запроса. Файлы блокировок теперь сохраняют свои inode; новые блокировки используют фиксированный пул из 256 слотов на пользователя. Коллизия отменяет только необязательную подготовку, не блокируя звук.
6. **Параллельная смена обложки и удаление песни могли оставить новую обложку без записи в библиотеке.** Редактирование и удаление получают актуальную строку под FOR UPDATE и завершают транзакцию до удаления предыдущих файлов.

Unit-проверки включают разделение общих OAuth настроек и личных подключений, доступ создателя/администратора, private permissions, state владельца и времени, смену OAuth клиента, запоздалый 401, отменённый callback, новую авторизацию после отключения и сохранение метки при записи токенов. Два процесса моделируют disconnect во время ранее начатой записи обновления без обращений к Google.

Stream-проверки включают Safari probe `bytes=0-1`, suffix/open-ended/неудовлетворимые Range, 200 fallback при проигнорированном Range, точную склейку кэша и остатка одной ревизии, отсутствие лишних/пропущенных байтов, 401/403/404/416/429/500, неверные Content-Range/Content-Length/encoding, оборванный поток и нормальную отмену анализатора, недоступный диск, TTL, изоляцию пользователей и подключений, бюджеты 32/128 МиБ, стабильность уже открытых блокировок и предел пула.

Repository-проверки используют только собственные записи с префиксом `__reel_test_`. Проверены чужие владельцы, CRUD плейлистов и треков, порядок, повторное членство, избранное и длительность, сохранение текущей обложки, удаление файлов. Параллельный импорт проверен двумя отдельными MySQL соединениями: первый matching INSERT оставался незавершённым, пока второй INSERT ждал его commit. Параллельное удаление проверено при незавершённой смене cover_path; удалена именно последняя обложка.

## Изоляция и границы

Все созданные данные сценариев, фикстуры, PHP sessions, cache и логи размещались в уникальных каталогах корневой `tests/.tmp/` и удалены после проверки. Библиотека пользователя и рабочие OAuth файлы не читались и не менялись. Подменные токены и аудиоданные были искусственными. Процессы конкурентных сценариев завершены и собраны родительским процессом.

Настоящий обмен OAuth и HTTPS скачивание из Google в этих серверных сценариях не запускались. Проверки ошибок upstream используют контролируемый reader реального DriveStream/DriveCache; это не подтверждение доступности внешнего аккаунта Google. Браузерная проверка интерфейса, PWA, аудиоанализатора и визуальных состояний проводится отдельно.
