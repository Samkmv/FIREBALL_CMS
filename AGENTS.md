# Правила работы с FIREBALL CMS

## Тесты и вспомогательные файлы

По требованию владельца проекта все создаваемые агентом файлы для проверок
должны находиться в корневой папке `tests/` этого проекта.

- Новые тестовые сценарии и вспомогательные скрипты размещать в `tests/`.
- Временные данные каждой проверки хранить в отдельной папке
  `tests/.tmp/<имя-задачи>-<уникальный-id>/`: тестовые базы, фикстуры, аудио,
  конфигурации, логи, HTML-превью, скачанные тестовые зависимости и другие
  сгенерированные файлы. При необходимости использовать `mktemp -d` с шаблоном
  внутри `tests/.tmp/`, а не системную временную папку.
- Скриншоты и отчёты, которые нужны для передачи результата, сохранять в
  `tests/artifacts/<имя-задачи>/`. В ответах давать ссылки на эти файлы.
- Не использовать для своих проверок системную `/tmp`, `tmp/` CMS, `storage/`,
  `public/uploads/` или другие папки движка. Пути временных файлов, профилей
  браузера и сессий тестового PHP задавать явно внутри `tests/.tmp/`.
- После проверки останавливать запущенные для неё процессы и убирать её
  временные данные. Удалять только собственные, точно установленные временные
  пути; не очищать всю `tests/` и не трогать чужие проверки, исходники тестов или
  результаты, которые ещё нужны пользователю.
- Использовать уже предоставленные средой зависимости без переноса их файлов.
  Это правило не требует менять штатные пути кэша, журналов, сессий и прочих
  рабочих данных самой CMS или операционной системы.

Существующие исходники тестов можно редактировать на их текущем месте; это не
повод разбрасывать новые вспомогательные файлы или перемещать чужие файлы.
